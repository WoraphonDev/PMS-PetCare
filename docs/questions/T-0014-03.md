- Status: open
- Raised by: claude · T-0014 (card preparation) · 2026-10-22
- Context: foundation#rule-branch-version requires every `UPDATE` of a branch row to set `version = version + 1` in the same statement, and says PromptPay updates bump the version without an outbox event. #org-branch-technical-gates (1) defines a no-op only for PATCH (200 current DTO, no UPDATE, no version bump, no audit/outbox); G1 in §12 applies the same idea to hours PUT. Nothing says what a PUT with the value already stored does for this endpoint, or whether `updated_at` changes.
- Question: What happens when `promptpayId` equals the stored value, and what does an effective change write?

  (B) Every accepted PUT writes: UPDATE + version bump + audit even when the value is unchanged (full trail of every confirmation).
