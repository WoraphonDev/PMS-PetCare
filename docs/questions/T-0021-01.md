# T-0021-01 · Where does the worker report outbox lag and dead-letter count?
- Status: answered
- Raised by: claude · T-0021 (card preparation) · 2026-10-24
- Context:
  - ADR-0004 Consequences: "ต้อง monitor ความล่าช้าของ outbox และ dead-letter queue". PLAN-foundation lists T-0021 as "relay + dead-letter + **lag metric**".
  - There is no metrics stack yet: ADR-0001 lists no Prometheus/OpenTelemetry library, and hosting is still open (T-0030), so there is nothing to scrape or receive metrics.
  - `GET /api/v1/health` is public (T-0002); counts of pending events are internal operational data.
  - Values the card proposes: `pendingCount`, `oldestPendingAgeSeconds`, `deadLetterCount`.
- Question: How should the worker expose these values in MVP?
- Options:
  (A) **Structured log line** from the worker every 60 s: one JSON line `{"msg":"outbox.lag","pendingCount":…,"oldestPendingAgeSeconds":…,"deadLetterCount":…}` on stdout, plus a `warn` line when `oldestPendingAgeSeconds ≥ 300` or `deadLetterCount > 0`. If Valkey is unreachable the line still carries the DB values with `deadLetterCount: null`, plus a warning. No dependency, no endpoint; whatever host T-0030 picks can alert on log patterns. A metrics endpoint can replace it later with its own card.
  (B) **Prometheus endpoint** on the worker (`/metrics` on a separate internal port, `prom-client`, Apache-2.0): gauges with the same three values. Needs a new dependency, a new env var for the port, and a scraper that does not exist yet.
  (C) Add the values to `GET /health` of the API. Simple, but the endpoint is public and served by the `api` process, not the worker.
  — แนะนำ: A. It meets the ADR's "monitor" with no new dependency or exposed surface, and does not pre-decide the observability stack before T-0030. Thresholds (300 s, > 0) are operational defaults the human can change here.
- Answer: 2026-10-24 · Zo chose (A) via Friday: structured JSON log line `outbox.lag` from the worker every 60 s (`pendingCount`, `oldestPendingAgeSeconds`, `deadLetterCount`; `deadLetterCount: null` + warning when Valkey is unreachable), plus a `warn` line when `oldestPendingAgeSeconds ≥ 300` or `deadLetterCount > 0`. No metrics dependency or endpoint. Card: T-0021.
