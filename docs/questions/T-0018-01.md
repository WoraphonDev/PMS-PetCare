# T-0018-01 · audit.list contract: filters, cursor, item shape and PII
- Status: open
- Raised by: claude · T-0018 (card preparation) · 2026-10-23
- Context:
  - foundation#ep-audit.list: `GET /audit-logs?from&to&action&actorUserId&cursor` · `audit.read` (owner only) · newest → oldest, cursor pagination 50 per page. #scr-audit: table + filters.
  - #tbl-audit_log: `org_id` (null = platform-level), `actor_user_id` (null = system), `action`, `entity_type`, `entity_id`, `before`/`after` (changed fields only, no secrets), `ip`, `user_agent`, `occurred_at`.
  - F06: local dates are `YYYY-MM-DD` (Asia/Bangkok), instants are UTC. RLS limits rows to the caller's org; platform rows (`org_id` null) are invisible.
  - Not defined:
    - the item and page shape;
    - whether `from`/`to` are dates or instants, and inclusive or exclusive;
    - validation of `action`;
    - the cursor format;
    - whether `ip`/`user_agent` (personal data) are returned;
    - whether the actor's name is resolved.
- Question: What exactly does `GET /audit-logs` accept and return?
- Options:
  (A) Request:
    - query keys only those five (others → `VALIDATION_FAILED`);
    - `from`, `to`: local dates `YYYY-MM-DD` in Asia/Bangkok, both inclusive (`from` 00:00 to the end of `to`), `from <= to`, at most 366 days apart;
    - `action`: one of the §6 actions;
    - `actorUserId`: UUID (no match → empty page, not `NOT_FOUND`);
    - `cursor`: opaque string from the previous page; malformed → `VALIDATION_FAILED`.
    Response 200 `{ items: AuditEntry[], nextCursor: string | null }`:
    - 50 per page, ordered `occurredAt` desc, then `id` desc (stable under equal timestamps);
    - `AuditEntry = { id, occurredAt, action, entityType, entityId, actor: { userId, displayName } | null, before, after }`;
    - `actor.displayName` = the actor's `membership.display_name` in this shop (a removed member keeps it), else the account name;
    - `ip` and `userAgent` are **not** returned.
  (B) Same as A, but `from`/`to` are ISO instants (`from` inclusive, `to` exclusive).
  (C) Same as A, plus `ip` and `userAgent` in each item.
  — แนะนำ: A. The screen filters by day, and F06 says local dates are `YYYY-MM-DD`. Leaving out IP/user agent keeps personal data out of a screen that only needs who/what/when; they stay in the table for investigations.
