# T-0016-04 · Which roles may a managed account have?
- Status: answered
- Raised by: claude · T-0016 (card preparation) · 2026-10-23
- Context:
  - F09 says owner/manager create username + password accounts "ให้พนักงานที่ไม่มี email"; ¹ only stops a **manager** from creating owner/manager accounts. So, as written, an owner may create a managed **owner** or **manager**.
  - Managed accounts have no email recovery (F09): if such an owner forgets the password and every other owner is unavailable, nobody can reset it (a reset needs `staff.update`, which owner/manager have).
  - F01 requires at least one active owner; a managed owner would count.
- Question: May a managed account be created with role `owner` or `manager`?
- Options:
  (A) As written: owner may create any role; manager only branch roles (`front_desk`, `groomer`, `caretaker`).
  (B) Branch roles and `manager` only; `owner` cannot be a managed account (`VALIDATION_FAILED` at `role`).
  (C) Branch roles only (managed accounts are for staff without email; owners and managers must use a real email).
  — แนะนำ: A, because it is what the spec says today and adds no new rule. Choose B or C if the human wants every account with org-wide authority to have email recovery; that is a business rule the human must state, and it also limits T-0017 `staff.update` (promoting a managed account).
- Answer: 2026-10-23 · human chose (A) in chat: as written — an owner may create a managed account with any role; a manager only branch roles. Spec: foundation#rule-managed-account-roles.
