# T-0046-01 · No endpoint reads a branch's current opening hours
- Status: open
- Raised by: claude · T-0046 (card preparation) · 2026-10-24
- Context:
  - `#scr-settings-branch` has a เวลาเปิด-ปิด tab, so the web must show the current week before the user edits it.
  - The API has `PUT /branches/{branchId}/hours` (G1, returns the week) but **no GET**. §12 G4 says "schedule read API สำหรับ future consumers ไม่อยู่ในการ์ดนี้" and the T-0013 scope excluded a "new hours read". `Branch` DTO and `branch.list` do not include hours. Closures do have `GET /branches/{branchId}/closures`.
  - Without a read, the tab could only show defaults and the first save would overwrite whatever the week really is.
- Question: How does the hours tab read the current week?
- Options:
  (A) **New endpoint `branch.hours.get`:** `GET /branches/{branchId}/hours` · permission `org.settings.read` (same as `branch.closure.list`; F02 — branch roles only for their branches, other org / unknown → `NOT_FOUND`, malformed id → `VALIDATION_FAILED`) · 200 with exactly the G1 response projection `{ items: [{ weekday, opensAt, closesAt }] }` sorted by weekday · readable while suspended (F04) · no audit/outbox. Needs a human-approved §12 amendment and a small API card (number given by the human, lane `api`, ~60 non-test lines + integration tests) merged before T-0046.
  (B) Same endpoint as A, but implemented inside T-0046 (add `apps/api/src/modules/org/**`, `apps/api/test/org/**`, `packages/contracts/src/org/**` to its `allowed_paths`). One PR less, but mixes lanes and puts API work under a `human_review` web card.
  (C) Include hours in the `Branch` DTO (`hours: [...]`) for `branch.list`. No new route, but changes a merged contract for every caller and every list call loads 7 rows per branch.
  — แนะนำ: A. It follows the existing pattern (closures have their own GET), keeps the PUT/GET projection identical, and keeps the API change reviewable on its own. T-0046 stays blocked on the hours tab until it merges; closures and payment do not need it, but splitting the card again is not worth it.
