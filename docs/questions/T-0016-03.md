# T-0016-03 · staff.password.reset contract, target rules and session clearing
- Status: answered
- Raised by: claude · T-0016 (card preparation) · 2026-10-23
- Context:
  - foundation#ep-staff.password.reset: `PUT /staff/{membershipId}/password` · permission `staff.update` · `{ newPassword }` · F09 · audit `staff.password_reset`.
  - F09:
    - only managed accounts of the caller's own org (`MANAGED_ACCOUNT_ONLY`, 409);
    - after a reset, every session of that account is cleared;
    - a password set by owner/manager → `must_change_password = true`;
    - a manager cannot reset owner/manager accounts (¹).
  - §8: resetting an email account → `MANAGED_ACCOUNT_ONLY`.
  - F11: 10–128 characters. F07: another org's id → `NOT_FOUND`.
  - The existing reset flows (`resetPasswordWithToken`, `changePasswordKeepingSession`) change the password and delete sessions in one transaction.
  - Not defined:
    - the response;
    - what a `removed` membership or the caller's own membership answers;
    - the error precedence;
    - whether `must_change_password` is set again;
    - whether 2FA is touched;
    - the audit content.
- Question: What does a reset require, change and return?
- Options:
  (A) Strict body `{ newPassword }` (F11, not trimmed). Check order:
    1. guards;
    2. `membershipId` not a UUID / body → `VALIDATION_FAILED`;
    3. in one tenant transaction, lock the membership row: absent, other org, or `removed` → `NOT_FOUND`;
    4. re-read org status → `ORG_SUSPENDED`;
    5. manager caller and target role owner/manager → `FORBIDDEN`;
    6. target account not managed, or managed by another org → `MANAGED_ACCOUNT_ONLY`.
    - Write in the same transaction: new password hash (Better Auth's hasher), `must_change_password = true`, delete **every** session of that account (incl. its 2FA session markers), audit `staff.password_reset` (`entity_type 'membership'`, `entity_id` = membership id, `before`/`after` null; never the password or hash).
    - 2FA settings are not changed.
    - The caller may reset their own membership only if it is a managed account of this org (normal rules apply; no special case).
    - Response **204** without body.
  (B) Same as A, but `MANAGED_ACCOUNT_ONLY` (6) before the manager rule (5).
  (C) Same as A, but a reset does not set `must_change_password` (the staff keeps the password the owner chose).
  — แนะนำ: A. F09 says a password set by owner/manager must be changed at next login, and a reset is such a password. Checking the manager rule before the account type does not reveal to a manager whether an owner's account is managed.
- Answer: 2026-10-23 · human chose (A) in chat: 204; check order guards → `VALIDATION_FAILED` → `NOT_FOUND` (absent / other org / removed) → `ORG_SUSPENDED` re-check → manager rule `FORBIDDEN` → `MANAGED_ACCOUNT_ONLY`; new hash, `must_change_password = true`, every session deleted, 2FA unchanged, audit with `before`/`after` null. Spec: foundation#contract-staff-password-reset.
