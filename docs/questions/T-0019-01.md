# T-0019-01 · platform.org.list / platform.org.get contracts
- Status: answered
- Raised by: claude · T-0019 (card preparation) · 2026-10-23
- Context:
  - foundation#ep-platform.org.list: `GET /platform/orgs?q&status&cursor` · platform admin. #ep-platform.org.get: `GET /platform/orgs/{orgId}` · platform admin. Nothing else is defined.
  - #scr-platform-orgs: search shops, status, plan; a detail page that changes plan / suspends.
  - The existing `PlatformAdminGuard` (T-0010): no session → `UNAUTHENTICATED`, not admin → `FORBIDDEN`, 2FA not passed → `TWO_FACTOR_REQUIRED`. Platform admin is not an org role and sends no `X-Org-Id`.
  - Not defined:
    - what `q` matches;
    - the page size and order;
    - the item and detail shapes;
    - whether owner contact data (personal data) is shown;
    - the error for an unknown `orgId`.
- Question: What do the two read endpoints accept and return?
- Options:
  (A) List:
    - query keys only `q`, `status`, `cursor` (others → `VALIDATION_FAILED`);
    - `q` trimmed 1–100, case-insensitive substring of `slug` or `displayName`;
    - `status` ∈ `active`/`suspended`; opaque `cursor`;
    - 50 per page, `createdAt` desc then `id` desc;
    - 200 `{ items: PlatformOrgSummary[], nextCursor }` with `PlatformOrgSummary = { id, slug, displayName, status, plan: { code, name }, usage: { branches, staff }, createdAt }`.
    Detail:
    - `orgId` not a UUID → `VALIDATION_FAILED`; unknown → `NOT_FOUND`;
    - 200 `{ organization: Organization (#contract-org), subscription: { plan: { code, name, maxBranches, maxStaff, priceSatangPerMonth, isActive }, startedAt, currentPeriodEnd, note }, usage: { branches, staff: { active, pendingInvitations, total } }, owners: [{ userId, displayName, email, username }] }`;
    - `email` null for managed accounts; `owners` = active owner memberships, so the admin can contact the shop.
    Usage counts follow #rule-branch-capacity and #rule-staff-capacity.
  (B) Same as A, but `q` also matches owners' email addresses.
  (C) Same as A, without `owners` (no personal data on platform screens).
  — แนะนำ: A. The detail page must let the admin reach a shop before suspending or changing its plan, and owner email is the only contact data the system holds. Searching by email (B) widens personal-data lookup across shops without a stated need.
- Answer: 2026-10-23 · human chose (B) in chat: as (A), and `q` also matches active owners' email addresses (case-insensitive substring). Spec: foundation#contract-platform-org-read.
