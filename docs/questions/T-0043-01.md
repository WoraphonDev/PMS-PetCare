# T-0043-01 · Send `Content-Type: application/json` only when a body is sent?
- Status: open
- Raised by: claude · T-0043 · 2026-10-24
- Context:
  - T-0043 *Tests*: "`me.get` 200 → … request is `GET {baseUrl}/me` with `credentials: "include"` and `Accept`/`Content-Type` JSON". Read literally, every request carries `Content-Type: application/json`, even without a body.
  - Fastify's JSON parser rejects a request that says `Content-Type: application/json` but has an empty body (`FST_ERR_CTP_EMPTY_JSON_BODY`) for methods it parses (POST, PUT, PATCH, DELETE). Bodyless calls exist: `POST /auth/logout` (`packages/contracts/src/identity/auth.logout.ts`: "no body"), `DELETE /branches/{id}/closures/{closureId}`, `DELETE /staff/invitations/{id}`, `DELETE /staff/{id}`. `apps/api/src/create-app.ts` only rewrites a **missing** DELETE content-type (T-0013-01), not a JSON one.
  - So a client that always sends the header would break logout and every DELETE that later cards add — and those cards may not edit the client core (their `allowed_paths` list only `src/index.ts` and `src/endpoints/*`).
- Question: Which header rule should the client use?
- Options:
  (A) `Accept: application/json` on every request; `Content-Type: application/json` **only when a JSON body is sent**. The `me.get` test asserts `Accept` JSON and no body. Works for GET, bodyless POST/DELETE and every body request.
  (B) Literal card text: `Content-Type: application/json` on every request. Breaks `auth.logout` and DELETE calls unless the API is changed (an API card would have to accept empty JSON bodies).
  (C) Always send `Content-Type` and, for bodyless non-GET requests, send `{}` as the body. Breaks the T-0013 rule "GET/DELETE ไม่รับ request body; nonempty body → `VALIDATION_FAILED`".
  — แนะนำ: A. It is the standard rule, needs no API change, and keeps later cards inside their paths. **T-0043 implements A**; if a human chooses B or C, the header code and its tests are changed before merge.
