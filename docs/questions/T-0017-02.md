# T-0017-02 · staff.remove: effect on sessions and on managed accounts
- Status: answered
- Raised by: claude · T-0017 (card preparation) · 2026-10-23
- Context:
  - foundation#ep-staff.remove: `DELETE /staff/{membershipId}` · `staff.remove` · F01 · "ล้าง session ของผู้ใช้ใน org นี้" · audit `staff.removed`.
  - F09: removing a managed account disables it (login impossible). This already holds: `isManagedAccountActive` refuses a managed account whose owning membership is not active.
  - Sessions are per account, not per shop (Better Auth `session` has no org). A real-email user may belong to several shops; the org guard already re-checks `membership.status = 'active'` on every request, so a removed member loses access to this shop immediately even with a live session.
  - §14 lock order applies (subscription → membership). Removing frees a seat (#rule-staff-capacity).
- Question: What does a removal change, and which sessions are deleted?
- Options:
  (A) Check order:
    1. guards;
    2. id → `VALIDATION_FAILED`;
    3. phase 2: lock subscription, org status → `ORG_SUSPENDED`, lock target — absent / other org / already removed → `NOT_FOUND`;
    4. manager and target owner/manager → `FORBIDDEN` (incl. self);
    5. last active owner → `LAST_OWNER`.
    - Write: `status = 'removed'`, `updated_at`; `membership_branch` rows kept as history (a re-join via T-0042 replaces them); audit `staff.removed` (`entity_type 'membership'`, `before { status: 'active', role, branchIds }`, `after { status: 'removed' }`).
    - Sessions:
      - **managed account of this org** → delete all its sessions (the account is now disabled anyway);
      - **real-email account** → no sessions deleted (the guard already blocks this shop; other shops are unaffected).
    - Response **204**.
  (B) Same as A, but delete every session of the removed account in both cases (logs a real-email user out of their other shops too).
  (C) Same as A, but also delete `membership_branch` rows.
  — แนะนำ: A, and amend the spec wording "ล้าง session ของผู้ใช้ใน org นี้" to this precise meaning in §16. It removes access to this shop at once without punishing the user's other shops, and makes a managed account unusable everywhere, as F09 requires.
- Answer: 2026-10-23 · human chose (A) in chat: `status = 'removed'`, branch rows kept; delete every session only for a managed account of this org; real-email accounts keep their sessions (the org guard blocks this shop at once); 204; the endpoint wording amended.
