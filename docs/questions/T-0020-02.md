# T-0020-02 · Listing plans for the platform UI (no endpoint in the spec)
- Status: answered
- Raised by: claude · T-0020 (card preparation) · 2026-10-23
- Context:
  - #scr-platform-orgs lets the admin change a shop's plan, so the screen needs the list of plans to choose from. The spec has no endpoint that lists `plan` rows, and agents must not invent endpoints.
  - Plans are written only by migrations/seed (the runtime role cannot write `plan`).
- Question: How does the platform UI get the plans it can choose?
- Options:
  (A) Add `platform.plan.list` = `GET /platform/plans` (platform admin) → 200 `{ items: [{ code, name, maxBranches, maxStaff, priceSatangPerMonth, isActive }] }`, ordered by `code`, all plans (inactive marked), as a spec amendment in this card.
  (B) No endpoint; the admin types the plan code (only `mvp_free` exists in MVP).
  (C) Defer the endpoint to the platform UI card, which then needs its own spec amendment.
  — แนะนำ: A. It is small, read-only, and makes setPlan usable from the screen without typing codes; adding it now avoids blocking the UI card later.
- Answer: 2026-10-23 · human chose (A) in chat: add `platform.plan.list` = `GET /platform/plans` (platform admin) → `{ items: [{ code, name, maxBranches, maxStaff, priceSatangPerMonth, isActive }] }` ordered by `code`. Spec: foundation#contract-platform-plan-list.
