# T-0022-01 · i18n approach for pms-web (Thai only in MVP)
- Status: answered
- Raised by: claude · T-0022 (card preparation) · 2026-10-24
- Context:
  - AGENTS.md: user-facing strings are Thai via i18n message files. foundation §7: "ข้อความไทยอยู่ในไฟล์ i18n ตาม screen id".
  - ADR-0001 lists no i18n library. MVP has one language (th); no plural rules are needed in Thai; a few messages need values inserted (e.g. a shop name, a count vs limit on `scr-subscription`).
  - Many screen cards will add messages in parallel, so the file layout must not make every card edit one shared file.
- Question: Which i18n mechanism should the skeleton set up?
- Options:
  (A) **Small typed in-house helper, no dependency:** one file per screen id under `src/i18n/th/` (`common.ts`, `scr-auth-login.ts`, …) each exporting a plain object; a barrel combines them (one line per file, alphabetical). `t("scr-auth-login.submit")` and `t("scr-subscription.usage", { used, limit })` with `{name}` placeholders. Keys **and placeholders** are checked by TypeScript: an unknown/misspelled key, a missing placeholder value, an extra one, a wrong placeholder name or a wrong value type fails `typecheck` (the card tests each case with `@ts-expect-error`). Adding a language later = add `src/i18n/en/` with the same shape and a locale switch, or move to a library then.
  (B) **i18next + react-i18next** (MIT): JSON resources per screen namespace, `useTranslation("scr-auth-login")`. Full-featured (plurals, lazy namespaces, language detection) but two more dependencies, and type-safe keys need extra declaration setup.
  (C) **FormatJS / react-intl** (BSD-3): ICU messages. Strong formatting, heavier, ICU syntax overkill for Thai-only.
  — แนะนำ: A. Thai-only MVP needs lookup + placeholders, and compile-time key checks catch the most common agent mistake (a key that does not exist). Per-screen files keep parallel cards conflict-free. Dates/money use `Intl` (`th-TH`, satang → baht) helpers that later cards add regardless of the choice.
- Answer: 2026-10-24 · Zo chose (A) via Friday: small typed in-house helper, Thai only, one message file per screen id + `common`, keys and placeholders checked by TypeScript; no i18n dependency. Card: T-0022.
