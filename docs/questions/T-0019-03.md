# T-0019-03 · New module `platform`, cross-org reads and whether reads are audited
- Status: answered
- Raised by: claude · T-0019 (card preparation) · 2026-10-23
- Context:
  - No `platform` module exists yet; `PlatformAdminGuard` is in `apps/api/src/common/`.
  - ADR-0002: modules call each other only through `index.ts`. ADR-0003: cross-shop work uses a separate role/connection (`PLATFORM_DB`, BYPASSRLS) and writes `audit_log`.
  - Identity's `membershipsOf` already reads memberships across orgs on the platform connection.
  - §6 has only two platform actions (`platform.org_status_changed`, `platform.plan_changed`); agents must not invent actions.
  - Registry rule (AGENTS): the module list in `apps/api/src/create-app.ts` is one entry per line, alphabetical.
- Question: Where does the code live, which connection does each part use, and are platform reads audited?
- Options:
  (A) Code and connections:
    - new module `apps/api/src/modules/platform/` (controller + use cases), registered in `create-app.ts` (one line);
    - cross-org **reads** go through new read functions in the public APIs of `org` (organizations, owners, counts) and `subscription` (plan/subscription per org); these take the platform connection and filter explicitly;
    - **writes** to one shop run in that shop's tenant transaction (`withTenant(orgId)` on the runtime connection), through org/subscription public functions, so RLS still checks the shop.
    Reads are **not** audited: §6 has no action for them, and ADR-0003's audit requirement is met by auditing every platform write.
  (B) Same as A, plus a new §6 action `platform.org_viewed` written on every detail read.
  (C) The platform module reads the org/subscription tables directly on the platform connection (no new public functions in other modules).
  — แนะนำ: A. It keeps module boundaries (ADR-0002) and RLS on every write. Read auditing (B) is a policy choice for the human; the spec today audits only changes.
- Answer: 2026-10-23 · human chose (B) in chat: as (A) — new `platform` module; cross-shop reads through `org`/`subscription` public read functions on the platform connection; writes in the shop's tenant transaction — plus a new §6 action `platform.org_viewed` written on every detail read. Spec: foundation#rule-platform-module. Not decided by this answer: which `org_id` the row carries (and so whether the shop owner sees it). That is open in T-0019-04.
