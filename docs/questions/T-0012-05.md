# T-0012-05 · outbox payload and aggregateVersion for branch.created / branch.updated
- Status: answered
- Raised by: claude · T-0012 · 2026-10-21
- Context: foundation#ep-branch.create / #ep-branch.update require outbox `branch.created` / `branch.updated`. foundation#tbl-outbox_event and ADR-0004 §3 require `aggregate_version int not null` on every event, but no table has a version column (`branch` has none) and no spec/ADR defines how versions are derived; existing usages are DB tests that hard-code `1`. No payload shape is defined for any event. The card forbids schema changes and inventing an event-version convention.
- Question: What `aggregateVersion` and `payload` must `branch.created` / `branch.updated` carry?
- Constraint found: migration 0004 does `REVOKE SELECT, UPDATE, DELETE ON "outbox_event" FROM app_runtime`, so the runtime cannot derive a version by reading prior outbox rows.
- Options (all use `aggregateType = "branch"`, `aggregateId = branch.id`, `branchId = branch.id`; payload = Branch DTO after the change without `promptpayId`, plus `changedFields: string[]` for `branch.updated`):
  (A) Version = `updated_at` of the branch after the change in epoch milliseconds (create = `created_at` ms). Branch row locked `FOR UPDATE` before update and `now` from the injected clock; two updates in the same millisecond would produce an equal version — consumers must treat version as "last-write ordering", not a strict counter. Fits int? No — epoch ms exceeds int32, so this needs a schema change → effectively not viable with `integer`.
  (B) Version = constant `1` for every branch event; ordering relies on `occurred_at` (Q-0013 worker ordering). Honest "no versioning yet" until a schema card adds a counter.
  (C) Add a `version integer not null default 1` column to `branch` (incremented on each update) in a separate human-approved schema card before T-0012's outbox part; T-0012 blocked for that part meanwhile.
  — แนะนำ: C for correctness (ADR-0004 makes `aggregate_version` an idempotency/ordering field for external channels); B acceptable as an explicit interim decision if the human prefers to unblock T-0012 now. A is listed only to record why it does not fit `integer`.
- Answer: 2026-10-21 · Zo approved option C in chat: a proper `branch.version` column via a separate human-approved schema card; constant `1` (option B) is explicitly NOT approved. T-0012's outbox part stays blocked until that schema card is merged and the spec text is authoritative.
