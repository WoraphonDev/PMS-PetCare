# T-0021-03 · Events with no subscribed consumer: mark published (no backlog for later consumers)?
- Status: answered
- Raised by: claude · T-0021 (card review) · 2026-10-24
- Context:
  - Today `branch.created`, `branch.updated` and `branch.hours_changed` are written (#rule-branch-outbox, #rule-branch-schedule-outbox), but no consumer exists. #rule-branch-schedule-outbox already says the minimal event "ไม่ใช่ promise ว่ามี consumer พร้อมแล้ว".
  - The T-0021 draft marks an event with no subscriber as published without creating a job. Consequence: a consumer added later (e.g. Channel webhooks) **never receives events written before it was deployed**. It must start from current state (read the owner module's data), not from the outbox history.
  - Leaving such rows unpublished instead makes `pendingCount` and `oldestPendingAgeSeconds` grow without limit (the lag warning fires forever), and the partial index stops being small.
  - `outbox_event` has no per-consumer cursor column; adding one is a schema change.
- Question: What happens to an event that no registered consumer subscribes to when it is relayed?
- Options:
  (A) **Mark published, no job.** A consumer added later gets only events written after its deploy. Each future consumer card states how it initialises from current data (or a later replay tool re-relays a `published_at` range). Lag stays meaningful.
  (B) **Leave unpublished** until some consumer subscribes to its type. Later consumers get the full history, but lag metrics become meaningless for those types, and rows pile up with no bound until then.
  (C) **Mark published and also keep it in a retained BullMQ stream/queue** (`outbox-archive`) for a fixed time, so a new consumer can catch up within that window. Extra Valkey memory and a retention policy to choose.
  — แนะนำ: A. No consumer exists yet, events today are invalidation signals (`{ branchId, version }`), and a new consumer can always rebuild from current data. (B) breaks the lag report the ADR asks for; (C) adds storage policy with no current user. Choosing A makes "initialise from current data" a rule every future consumer card must cite.
- Answer: 2026-10-24 · Zo chose (A) via Friday: an event that has no subscribed consumer **at the moment it is relayed** is marked published without a job and is never re-sent to a consumer added later. Rows still pending when a consumer is added may be delivered to it. A later consumer initialises from current data (or a future replay tool). Card: T-0021.
