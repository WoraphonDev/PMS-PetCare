# T-0015-06 · "หรือสมัครใหม่ใน flow เดียวกัน" — invitees without an account
- Status: answered
- Raised by: claude · T-0015 (card preparation) · 2026-10-22 (revised after review 2026-10-22)
- Context:
  - foundation#ep-invitation.accept allows "user (หรือสมัครใหม่ใน flow เดียวกัน)", and #scr-invite-accept says "login หรือสมัครแล้วรับคำเชิญ".
  - `auth.signup` (#rule-signup-input, #rule-signup-atomic) always creates a new organization, branch and owner membership, and requires email verification before login (#rule-email-verification-http). There is no endpoint that creates only a user.
  - So an invitee without an account cannot accept today. Using `auth.signup` would create an unwanted shop of their own, which is not an acceptable workaround.
  - #accept-signup-verification already mentions a later "signup → verify → login → invite flow" (T-0029 release gate).
- Question: How does a person without an account join through an invitation, and where is that work tracked?
- Options:
  (A) Out of T-0015. **T-0015 supports only people who already have an account and are logged in.** A later spec amendment + card adds a user-only signup bound to an invitation token: no org created; the account's email = the invitation email; verification per a rule to decide then.
    - Tracked now in `docs/tasks/PLAN-foundation.md` as unnumbered follow-up work; the human gives it a card number when approving it.
    - T-0026 (staff screens, incl. `scr-invite-accept`) can ship the logged-in path first. Its "no account yet" path depends on that follow-up.
  (B) In T-0015: `POST /invitations/accept` also takes `{ token, password, name }` when there is no session, and creates the user, membership and session in one flow. This touches auth, email-verification, signup abuse limits and session creation, and would push T-0015 well past 600 lines.
  — แนะนำ: A. It keeps T-0015 inside the org module and the line limit. The new signup path needs its own spec section, abuse limits and probably `human_review`.
- Answer: 2026-10-22 · human chose (A) in chat: invite-bound signup (a user without a new shop) is separate follow-up work, not in T-0015 or T-0042; until then accept supports only people with an account who are logged in; `auth.signup` must not be used as a workaround. Spec: foundation#rule-invite-signup-followup.
