# T-0015-06 · "หรือสมัครใหม่ใน flow เดียวกัน" — signup while accepting
- Status: open
- Raised by: claude · T-0015 (card preparation) · 2026-10-22
- Context: foundation#ep-invitation.accept allows "user (หรือสมัครใหม่ใน flow เดียวกัน)" and #scr-invite-accept says "login หรือสมัครแล้วรับคำเชิญ". But `auth.signup` (#rule-signup-input, #rule-signup-atomic) always creates a new organization, branch and owner membership, and requires email verification before login (#rule-email-verification-http). There is no endpoint that creates only a user. So an invitee without an account cannot accept today without also creating a shop of their own.
- Question: How does a person without an account accept an invitation?
- Options:
  (A) Out of T-0015. T-0015 implements accept for a logged-in user only. A later spec amendment + card adds a user-only signup bound to an invitation token (no org created; email verified by the invitation itself or by the normal verify flow), and T-0026 waits for it.
  (B) In T-0015: `POST /invitations/accept` also takes `{ token, password, name }` when there is no session and creates the user (email = invitation email, treated as verified because the invitation link was emailed), membership and session in one flow.
  (C) Invitees must first sign up with `auth.signup` (creating their own shop) and then accept.
  — แนะนำ: A. B touches auth and email-verification rules (identity, signup abuse limits, rate limits, session creation) and would push T-0015 well past 600 lines; it needs its own spec section and probably `human_review`. C is a poor experience and creates unused shops.
