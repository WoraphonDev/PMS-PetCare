# T-0020-03 · `entity_type` / `entity_id` of the `platform.plan_changed` audit row
- Status: answered
- Raised by: claude · T-0020 · 2026-10-24
- Context:
  - foundation#contract-platform-set-plan fixes `org_id` (the target shop), `before`/`after` (only `planCode` / `currentPeriodEnd` that changed) and "no `note`". It does not name `entity_type` / `entity_id`. Both columns are `not null` (#tbl-audit_log).
  - `platform.org_status_changed` uses `entity_type 'organization'`, `entity_id` = org id (#contract-platform-org-status). Every other action names the row it changed (`organization`, `branch`, `membership` …).
  - `audit.list` returns `entityType` / `entityId` to the shop owner (#contract-audit-list), so the choice is visible.
- Question: Which entity does a `platform.plan_changed` row name?
- Options:
  (A) `entity_type 'subscription'`, `entity_id` = the subscription row's id: the row that changed, like every other action.
  (B) `entity_type 'organization'`, `entity_id` = org id: the same as `platform.org_status_changed`, so all platform actions on a shop point at the shop.
  — แนะนำ: A. The audit row then names the row whose fields are in `before`/`after`. B is fine if the UI should group every platform action under the shop.
- Answer: 2026-10-26 · human chose (A) in chat: `entity_type 'subscription'`, `entity_id` = the subscription row's id — as already implemented in `apps/api/src/modules/subscription/platform-writes.ts` (T-0020).
