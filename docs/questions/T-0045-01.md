# T-0045-01 · `routes/login.2fa.tsx` nests under `/login`, so `/login/2fa` shows the login form
- Status: open
- Raised by: claude · T-0045 · 2026-10-24
- Context:
  - T-0045 `allowed_paths` lists `apps/pms-web/src/routes/login.2fa.tsx` for `scr-auth-2fa` (`/login/2fa`).
  - In TanStack Router file-based routing, `login.2fa.tsx` is a **child** of `login.tsx`. The generated tree confirms it (`src/routeTree.gen.ts`: `Login2faRoute … getParentRoute: () => LoginRoute`). A child renders only inside the parent's `<Outlet />`.
  - `login.tsx` (T-0023) renders `LoginScreen` (`src/features/auth/login-screen.tsx`), which has no `<Outlet />`. So opening `/login/2fa` shows the login form, and the 2FA screen never appears. All 7 T-0045 2FA tests fail for this reason; every other T-0045 screen and test passes.
  - Both fixes touch a file outside T-0045's `allowed_paths`.
  - Checked locally: with the file renamed to `login_.2fa.tsx` (option A) the generated route has `getParentRoute: () => rootRouteImport` and all 77 pms-web tests pass; the branch keeps the card's file name until this is answered.
- Question: Which file change should T-0045 make so `/login/2fa` renders the 2FA screen?
- Options:
  (A) **Un-nest the route by renaming it to `routes/login_.2fa.tsx`** (TanStack's trailing `_` = "same URL prefix, not a child"). URL stays `/login/2fa`; `login.tsx` and `LoginScreen` are untouched. Needs `allowed_paths` to list `apps/pms-web/src/routes/login_.2fa.tsx` instead of `login.2fa.tsx`.
  (B) Make `/login` a layout: `login.tsx` renders `<Outlet />` and the form moves to `login.index.tsx`. Touches two T-0023 files and changes the route structure other cards may rely on.
  (C) Use a different URL for the 2FA screen. Changes the §7 path `/login/2fa`; needs a spec change.
  — แนะนำ: A. Smallest change, keeps the spec URL and leaves T-0023's files alone. Only the card's `allowed_paths` entry changes (a human edit).
