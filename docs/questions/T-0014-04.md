# T-0014-04 · Audit `branch.payment_settings_updated` before/after content
- Status: open
- Raised by: claude · T-0014 (card preparation) · 2026-10-22
- Context: §6 lists the action `branch.payment_settings_updated` but not its payload. foundation#tbl-audit_log: `before`/`after` hold only changed fields and must not contain secrets/tokens. A PromptPay ID may be the owner's personal mobile number or national ID, which is personal data; AGENTS.md forbids logging PII (application logs). On the other hand, the value is shown to customers on the QR and is already in the `Branch` DTO for every `org.settings.read` role (T-0012-02), and `audit.read` is owner-only. The point of auditing this change is to investigate a payout account being redirected.
- Question: What goes into `before`/`after`, `entity_type` and `entity_id`?
- Options:
  (A) `entity_type = 'branch'`, `entity_id = branch.id`, `before = { promptpayId: <old or null> }`, `after = { promptpayId: <new or null> }` with the full values. No application log line contains the value.
  (B) Same as A but values masked (e.g. last 4 digits only: `"******5678"`).
  (C) Same entity, but `before`/`after` = `null` (only the fact that it changed is recorded).
  — แนะนำ: A. Full values are needed to prove which account payments were redirected to, the data is not secret (it is printed on the QR), and the audit table is owner-only and append-only. If the human prefers masking, B is the next best.
