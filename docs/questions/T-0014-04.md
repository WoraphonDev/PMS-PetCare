# T-0014-04 · Audit `branch.payment_settings_updated` before/after content
- Status: answered
- Raised by: claude · T-0014 (card preparation) · 2026-10-22
- Context: §6 lists the action `branch.payment_settings_updated` but not its payload. foundation#tbl-audit_log: `before`/`after` hold only changed fields and must not contain secrets/tokens. A PromptPay ID may be the owner's personal mobile number or national ID, which is personal data; AGENTS.md forbids logging PII (application logs). The value is also in the `Branch` DTO for every `org.settings.read` role (T-0012-02), and `audit.read` is owner-only. The point of auditing this change is to investigate a payout account being redirected.
- Question: What goes into `before`/`after`, `entity_type` and `entity_id`?
- Options:
  (A) `entity_type = 'branch'`, `entity_id = branch.id`, `before = { promptpayId: <old or null> }`, `after = { promptpayId: <new or null> }` with the full values. No application log line contains the value.
  (B) Same as A but values masked (e.g. last 4 digits only: `"******5678"`).
  (C) Same entity, but `before`/`after` = `null` (only the fact that it changed is recorded).
  — แนะนำ (เดิม): A. Full values are needed to prove which account payments were redirected to, and the audit table is owner-only and append-only. If the human prefers masking, B is the next best.
  — Correction (2026-10-22): the original draft also argued the value "is not secret because it is printed on the QR". That reasoning is withdrawn: disclosing an ID so customers can pay does not by itself permit keeping copies of it in the audit trail.
- Answer: 2026-10-22 · human chose (B) for MVP in chat: `entity_type = 'branch'`, `entity_id = branch.id`; `before`/`after` = `{ promptpayId }` masked — every digit before the last 4 replaced by `*` (10 digits → `******5678`, 13 digits → `*********5678`); `null` stays `null`. The full value must not appear in the audit payload, application logs or error messages. Masking applies to audit only; the stored branch value and the `Branch` DTO are unchanged. Spec: foundation#rule-branch-payment-settings-audit.
