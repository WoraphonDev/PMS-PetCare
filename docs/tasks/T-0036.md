# T-0036 · Verified real-email login with managed exception

## Goal

ทำเฉพาะขอบเขตใบนี้ตาม business decisions ที่อนุมัติแล้ว; technical design ใน spec amendment ต้อง merge โดยมนุษย์ก่อน execution

## Read first

- `docs/spec/features/foundation.md#rule-email-login-policy`
- `docs/spec/features/foundation.md#rule-signup-atomic`, `#rule-email-verification-state`, `#rule-email-verification-http`, `#rule-signup-abuse`, `#rule-email-login-policy`, `#accept-signup-verification`, `#errors`
- `docs/spec/01-conventions.md`; ADR-0002, ADR-0003, ADR-0005, ADR-0006

## Deliverables

- app-level verification gate both login modes without global requireEmailVerification breaking managed users; no signup/signin auto-send/session bypass
- preserve F09, F10, failure limiter, mustChangePassword and password reset/change behavior
- activation/release ต้องพร้อม working legacy resend/verification recovery ตาม `#accept-signup-verification`; ไม่เพิ่ม T-0023 dependency cycle และไม่ bypass verified-login policy
- fixtures explicitly mark genuinely verified real-email accounts; legacy unverified fixtures remain for negative tests ไม่ mass set true เพื่อทำ test เขียว

## Tests (เขียนก่อน)

- email+username real unverified (including legacy) → UNAUTHENTICATED, failure quota consumed, zero session/cookie; verified correct credentials pass; wrong password normal failure
- active managed unverified login retains mustChangePassword/2FA; removed managed denied; real-email with managed.invalid suffix not exempt unless isManaged
- resend+verify restores legacy login; reset password does not implicitly verify; existing password/2FA/trust-device/security/timing tests pass
- internal cookie/session not produced before verification gate; no auto verification email on sign-in

## Dependencies
