## Goal

Owner and manager set a branch's weekly opening hours and holidays; the owner sets the branch's PromptPay ID.

## Design

### เวลาเปิด-ปิด — `/settings/branches/:branchId/hours` (owner, manager)

- Load the current week with `GET /branches/{branchId}/hours` (T-0049; same `{ items: [{ weekday, opensAt, closesAt }] }` projection as the PUT response).
- Seven rows, จันทร์ … อาทิตย์ (ISO 1–7): "ปิดทั้งวัน" toggle, or open/close times `HH:mm` (native `<input type="time">`, value kept as `HH:mm`, no seconds). Client checks per G1: both null or both set and `opensAt < closesAt`; no overnight.
- Save → `PUT /branches/{id}/hours` with all 7 items → 200 → replace the form with the response. No-op saves are allowed (the API answers 200 without a change).

### วันหยุด — `/settings/branches/:branchId/closures` (owner, manager)

- `GET /branches/{id}/closures` → list sorted as the API returns (startDate, endDate): date range with `formatDate` from T-0024 (`th-TH`, Buddhist year), reason.
- Add: `startDate`, `endDate` (native date inputs → `YYYY-MM-DD`; `startDate <= endDate`), `reason` (optional, ≤ 500) → `POST` → 201 → refetch. Past and overlapping ranges are allowed (G3) — no client check against them.
- Delete with a confirm step → `DELETE` → 204 → refetch; `NOT_FOUND` (already deleted) → refetch + `alreadyDeleted`.

### การชำระเงิน — `/settings/branches/:branchId/payment` (owner only)

- Shows the current `promptpayId` from the Branch DTO. One field: PromptPay ID (mobile `0xxxxxxxxx` or 13-digit tax ID with valid checksum — F08 / §13, client-checked with the contract schema) or empty to clear — the contract requires the key and `null` clears the value (`branch.payment_settings.update.ts`).
- Save → `PUT /branches/{id}/payment-settings` `{ promptpayId }` → 200 → update the branch in the `branch.list` cache.
- Non-owner opening the URL → `errors.FORBIDDEN` text, no request.
- No QR preview in this card (no spec screen for it).

### Common

- `ORG_SUSPENDED`, `FORBIDDEN`, `NOT_FOUND` (branch gone) → `errors.ts` / not-found state; `VALIDATION_FAILED` → field messages (G1 per-weekday errors map to the right row).
- api-client: `branch.hours.get`, `branch.hours.put`, `branch.closure.list`, `branch.closure.create`, `branch.closure.delete`, `branch.paymentSettings.update`.

## Tests (write first)

- api-client descriptors (incl. DELETE without body, 204).
- hours: loads the week; closed toggle sends `null`/`null`; invalid range blocks save; PUT body has exactly 7 items in weekday order with `HH:mm`; per-row server error mapping; 200 replaces form.
- closures: list order and Thai date format (Buddhist year); add with/without reason (empty reason → `null`; the contract defaults it to `null`); `startDate > endDate` blocked; past/overlapping allowed; delete confirm → request → refetch; `NOT_FOUND` → `alreadyDeleted`.
- payment: owner-only (manager sees forbidden text, no request); F08 client check (bad checksum, wrong length); 200 updates the branch cache; `VALIDATION_FAILED` mapping.
