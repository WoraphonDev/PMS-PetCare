## Selected contracts (resolved proposal, not an execution approval)

- G1 → `#contract-branch-hours`: strict seven-item HH:mm/null replacement, 200 sorted projection, preserve rows, semantic no-op has no side effects.
- G2 → `#contract-branch-closures`: strict POST, optional trimmed 1–500 code-point reason/null; 201 exact Closure DTO; item DELETE 204/repeat NOT_FOUND; GET all rows sorted startDate/endDate/id, no pagination.
- G3 → `#rule-branch-closure-calendar`: real Gregorian 0001–9999 inclusive local ranges, overlap/duplicates/past allowed; no retroactive booking mutation.
- G4 → `#rule-branch-schedule-outbox`: parent-first lock, atomic parent increment/timestamp, one minimal `{ branchId, version }` event per effective write; transactional rollback.
- G5 → `#rule-branch-schedule-audit`: no new/reused schedule audit. Common endpoint errors/UUID/body/query rules are explicit in `#contract-branch-schedule-common`.

## Tests (write first)

Use actual PostgreSQL through existing Testcontainers runtime-role harness (existing API harness also boots Valkey). Do not replace transaction/RLS/race coverage with mock repositories. Error assertions include status, canonical envelope, fields and absence of side effects.

| Area | Required cases |
|---|---|
| Hours | Approved happy response/ordering, all seven days, all-closed and mixed schedules; six/eight items, missing/duplicate/0/8/fractional weekdays; null mismatch; equal/reversed/overnight/invalid times; lexical boundaries/precision per G1; omitted keys, wrong types, arrays/null body; nested unknown and prototype-like keys; semantic no-op/row-ID/timestamp policy per G1; persisted seconds are not silently truncated in comparison; missing persisted day => INTERNAL without repair. |
| Closure create | Single-day and multi-day; omitted/null/trimmed reason and 1–500 code-point bounds, astral Unicode, U+0000/lone-surrogate rejection; invalid calendar dates/leap-year boundaries (1900/2000), year 0000 rejected, 0001/0099/0100/9999 accepted, expanded/BC/infinity rejected, reversed ranges, datetime/offset instead of local date, unknown/system/tenant keys; past/overlap/duplicate behavior exactly as G3. |
| Closure delete/list | Correct resource binding; same-org wrong-branch closure, other-org closure, missing IDs and malformed IDs; repeated delete per G2; empty list; approved ordering, DTO null keys/timestamps, no orgId leak; hours exact projection omits row IDs/timestamps/branchId/version; no writes/events/audit on GET. |
| Roles | Owner/manager succeed on every write; front_desk/groomer/caretaker receive FORBIDDEN on assigned-branch writes. All five roles read closure list within scope; branch roles get NOT_FOUND on unassigned branches. Platform flag alone must not bypass membership. |
| Common errors | Each route: UNAUTHENTICATED missing/expired session; VALIDATION_FAILED bad/missing X-Org-Id and malformed path/body; unsupported queries (including duplicate keys) rejected on all routes; GET/DELETE nonempty bodies rejected, absent/zero-byte body accepted; FORBIDDEN foreign/no-membership org header; PASSWORD_CHANGE_REQUIRED. Writes ORG_SUSPENDED; suspended GET succeeds. Authorized caller's absent/foreign branch => NOT_FOUND on all four endpoints, with no leakage or writes. INTERNAL DB/outbox failure sanitized. No schedule CONFLICT (overlaps are allowed); no unrelated PLAN_LIMIT_REACHED/RATE_LIMITED errors invented. |
| Atomicity | Force failure after child writes and during event enqueue; prove children, parent version/timestamps and event all roll back. No schedule audit is written; existing branch audit behavior remains intact. Reads/rejections/no-op policy produce no unintended effects. Runtime role is non-superuser/non-owner/NOBYPASSRLS; foreign/no-context tenant rows inaccessible using existing harness assertions. |
| Concurrency | Parallel hours replacements never leave mixed weeks; closure creates/deletes and branch.update serialize on same parent; each effective write receives unique monotonic parent/event version with matching approved payload; two deletes of one closure follow G2 with only one successful deletion/event; other branches/tenants unaffected. Simultaneous overlapping/identical inserts both succeed as independent records, with distinct parent versions/events. |
| Time/privacy | Fixed injected clock for every app-written instant; local dates round-trip without timezone shift and inclusive boundary per G3; no PromptPay/tokens/internal exceptions in event/error. |
