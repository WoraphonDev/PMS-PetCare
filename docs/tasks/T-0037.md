## Deliverables

- identity limiter factory/public tokens: atomic signup single counter and resend dual counter operation; separate namespaces; fixed first-attempt TTL; errors fail closed/suppress per caller contract
- explicit trusted-proxy IP source integration using current config/create-app paths; default untrusted X-Forwarded-For ไม่เพิ่ม infrastructure assumption
- pure limiter ports available for T-0035/T-0011; no login/forgot policy changes; no new package dependency/Valkey deployment topology guarantee

## Tests (เขียนก่อน)

- real Valkey concurrent signup exactly 5 admitted, sixth blocked; conflicts counted at caller; malformed schema not counted; TTL does not extend
- resend 3/email AND 10/IP across mixed IP/email; every valid attempt increments both even when counterpart over-limit, unknown/verified/managed same counting; simultaneous calls not overshoot
- Valkey down/null/command-error results never admit; signup INTERNAL/resend suppress signal; fixed expiry from first attempt, no send-failure refund
- spoofed X-Forwarded-For ignored without explicit trusted proxy; trusted source only when configured; login/forgot namespace and behavior regressions
- verify standalone Valkey real deployment assumption; cluster multi-key atomicity unsupported until explicit topology/key-slot design proved
