# T-0009 · Tenant RequestContext + guards

## Goal

ทุก endpoint ในร้านได้ `ctx` ที่รู้ว่า **ใคร · ร้านไหน · บทบาทอะไร · สาขาไหน** และ `ctx.db` ที่ผูก RLS กับร้านนั้นแล้ว — use case ไม่ต้องจัดการเอง
นี่คือฐานของ "org อื่น → NOT_FOUND" ทุก endpoint ต่อจากนี้

## Deliverables

- `packages/domain/src/permissions.ts`: `Permission` (ทุกแถวของตาราง `#permissions`), `can(role, permission): boolean` ตามตารางทีละช่อง, `isOrgWideRole(role)`
  (manager จัดการ owner/manager ไม่ได้ — ¹ — เป็นฟังก์ชันแยก `canManageMember(actorRole, targetRole)`)
- `apps/api/src/common/context.ts`: ขยาย `RequestContext` → `user`, `org`, `membership` (`role`, `branchIds`), `db` (tenant-scoped)
- decorators/guards ใน `apps/api/src/common/`:
  - `@OrgScoped()` — อ่าน `X-Org-Id`; ไม่มี/ผิดรูป → `VALIDATION_FAILED`; ผู้ใช้ไม่มี membership `active` ใน org นั้น → `FORBIDDEN` (F07: id ใน header ไม่ใช่ทรัพยากร จึงไม่ใช่ NOT_FOUND)
  - `@RequirePermission(p)` — ไม่มีสิทธิ์ → `FORBIDDEN`
  - `ctx.branchScope` — role ระดับสาขาเห็นเฉพาะ `branchIds` (F02); helper `assertBranchInScope(ctx, branchId)` → `NOT_FOUND` ถ้าอยู่นอกขอบเขต
  - org `suspended` → ทุก method ที่ไม่ใช่ GET/HEAD → `ORG_SUSPENDED` (F04)
  - `must_change_password` → ทุก endpoint ยกเว้น `auth.passwordChange`, `auth.logout`, `me.get` → `PASSWORD_CHANGE_REQUIRED` (F09)
  - `ctx.db.run(fn)` = `withTenant(runtimeDb, org.id, fn)` — **ไม่มีทางอื่น** ให้ use case แตะตารางของร้าน
- `apps/api/src/modules/org/permissions.ts`: re-export สิทธิ์ให้ controller ใช้
- `apps/api/test/support/seed.ts`: `seedOrg({ role, branches })` สร้าง user + org + branch + membership แล้วคืน cookie + `X-Org-Id` สำหรับ test ทุกการ์ดต่อจากนี้

## Tests (เขียนก่อน)

- `packages/domain/test/permissions.test.ts`: ตาราง `#permissions` ทุกช่อง (role × permission) เขียนเป็น literal ใน test; `canManageMember` ครบทุกคู่
- `apps/api/test/common/*.test.ts` ผ่าน probe controller:
  - ไม่มี session → 401 · ไม่มี `X-Org-Id` → 400 · org ที่ไม่ได้เป็นสมาชิก → 403 · membership `removed` → 403
  - role ไม่มี permission → 403 · groomer สาขา A ขอข้อมูลสาขา B → 404
  - org `suspended`: GET ผ่าน, POST → 423 `ORG_SUSPENDED`
  - `must_change_password`: probe → 403 `PASSWORD_CHANGE_REQUIRED`; `/me` ยังผ่าน
  - `ctx.db` เห็นเฉพาะข้อมูลของ org ใน header (มีข้อมูล org อื่นใน fixture)
