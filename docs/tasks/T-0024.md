> Drafted by an agent at the human's request on 2026-10-24. T-0024-01 is **answered (A)** in chat on 2026-10-24: the web imports the permission table from `@app/domain`. **Do not start implementation until a human has merged the ADR-0002 amendment (PR #66) and this card.** The Thai copy below is approved by merging this card. ## Goal

Every logged-in page sits in one shell that knows who the user is, which shop and branch they work in, shows only the menu items their role may open, warns when the shop is suspended, and sends requests with the right `X-Org-Id`. Logged-out users and users who must change their password are sent to the right page.

## Design

### Routes and guard

- Public routes (no session needed): `/signup`, `/login`, `/login/2fa`, `/verify-email`, `/forgot-password`, `/reset-password`, `/invite`; `/change-password` is outside `_app` too (it handles its own errors). Everything else lives under a pathless layout route `_app` that loads `me.get` (TanStack Query, key `["me"]`).
- **Home is `_app.index.tsx`.** This card **deletes** the T-0022 placeholder `src/routes/index.tsx` (a child of the root, so it would bypass the guard) and adds `src/routes/_app.index.tsx` for `/`, so `/` gets the guard and the shell. No other file defines `/`.
- `_app` guard, in order:
  1. `me.get` → `UNAUTHENTICATED` → navigate to `/login` (no return-URL in MVP);
  2. `user.mustChangePassword` → navigate to `/change-password` (F09);
  3. otherwise render the shell.
- A logged-in user (cached `me` present) opening `/login` or `/signup` → navigate to `/`.
- **Session-expiry redirect — only for requests that need a session from inside `_app`.** The API also uses `UNAUTHENTICATED` as an ordinary answer in credential flows (wrong login, wrong 2FA code or expired pending session, wrong current password, wrong password/code on 2FA enable/disable) and public pages must render without a session, so there is **no** blanket handler.
  - Queries and mutations opt in with an explicit meta flag `meta: { sessionRequired: true }`. The `QueryCache` / `MutationCache` `onError` handlers act **only** when that flag is set:
    - `UNAUTHENTICATED` → clear the query cache and navigate to `/login`;
    - `PASSWORD_CHANGE_REQUIRED` → navigate to `/change-password` (never when already on `/change-password`).
  - The flag is set by: the `_app` `me.get` guard query, and every query/mutation built through `useOrgApi()` (org-scoped data).
  - The flag is **never** set for credential calls, even inside `_app`: `auth.login`, `auth.twoFactor.verify` / `.enable` / `.disable`, `auth.passwordChange`, `auth.passwordForgot` / `.passwordReset`, `auth.signup`, `auth.email.*`, `auth.signupWithInvitation`, `invitation.preview`, `invitation.accept`. Their screens handle `UNAUTHENTICATED` themselves (T-0023, T-0045, T-0047, T-0048).
  - Public routes never create flagged requests; `/invite` and `/verify-email` render and work with no session.
  - Other error codes always stay with the screen.

### Org and branch context (`scr-org-switcher`)

- Current org = the remembered org id for this user if it is still in `me.memberships`, else the first membership. Remember per user in `localStorage` key `pms.ctx.<userId>` = `{ orgId, branchId }` (wrapped in try/catch — private mode must still work).
- Current branch = remembered branch if it is in that membership's `branches`, else the first branch; `null` when the list is empty.
- `useOrgApi()` returns the api client bound to the current org: every org-scoped request sends `X-Org-Id`. Public/user endpoints (`me.get`, `auth.*`, `invitations/accept`, `platform.*`) do not.
- **Switching org clears every org-scoped query** (`queryClient.removeQueries` for all keys except `["me"]`) before the new org renders, so data of one shop is never shown under another.
- No membership: the shell shows `noOrg` (and, for a platform admin, a link to `/platform/orgs`).
- Header menu: shop display name + role label (`#roles` labels), list of other shops, branch picker (hidden when the membership has ≤ 1 branch), account link `/account/security`, logout.

### Navigation (per §7 "ผู้ใช้")

| item | path | shown to |
|---|---|---|
| ตั้งค่าร้าน | `/settings/org` | owner |
| สาขา | `/settings/branches` | owner, manager |
| พนักงาน | `/settings/staff` | owner, manager, front_desk |
| ประวัติการใช้งาน (audit) | `/settings/audit` | owner |
| แพ็กเกจ | `/settings/subscription` | owner, manager |
| ความปลอดภัยบัญชี | `/account/security` | every user |
| ผู้ดูแลแพลตฟอร์ม | `/platform/orgs` | `user.isPlatformAdmin` |

- `src/lib/permissions.ts` exposes `canSee(screen, role)` and re-exports the permission checks later screens use for buttons — `can(role, permission)` and `canManageMember` imported from `@app/domain` (T-0024-01 A); no copy of the table in the web. The API stays the authority; hiding is convenience only.
- Items whose page is not built yet still appear (routes come with T-0025…T-0028, T-0046…T-0048); until then they show the T-0022 not-found page.

### `/` (home)

The shell with the shop name and the role label and the nav; no data beyond `me.get`. (No dashboard screen exists in the spec.)

### Date helpers — `src/lib/format.ts` (shared by later screens)

- `formatDate(iso | localDate)`, `formatDateTime(iso)`: `th-TH`, Buddhist year, time zone `Asia/Bangkok` (F06).
- `bangkokDayStartUtc(localDate)` → ISO instant of `YYYY-MM-DD 00:00` in Bangkok (UTC+7, no DST).
- Money formatting is **not** here: `formatBaht` is added by T-0027 (human review).

### Suspended banner (F04)

When the current org's `status` is `suspended`, a persistent banner `suspended` at the top of every page under `_app`. Writes still fail server-side with `ORG_SUSPENDED` (shown by each screen via `errors.ts`).

### Logout

`POST /auth/logout` (add descriptor) → clear the whole query cache and the in-memory context (keep `localStorage` so the next login reopens the same shop) → `/login`. A failed logout request still clears local state and navigates.

## Tests (write first)

- guard: `UNAUTHENTICATED` → `/login`; `mustChangePassword` → `/change-password`; logged-in on `/login` → `/`; public routes render without `me.get`.
- **`/` without a session → `/login`** (home is under `_app`); `/` with a session renders the shell; `src/routes/index.tsx` no longer exists (the generated route tree has exactly one `/`).
- context: remembered org used when still a member; removed org → first membership; per-user key; `localStorage` throwing → still works; branch fallback rules; `noOrg` state (+ platform link only for admins).
- `X-Org-Id`: org-scoped request carries the current org; `me.get`/`auth.*` do not.
- **switching org removes org-scoped cached data** (a query cached for org A is gone after switching to B; `["me"]` stays).
- nav: for each role the exact item set of the table; platform item only for `isPlatformAdmin`.
- `permissions.ts` re-exports the functions of `@app/domain` (identity check: `can === domain.can`), so the web never holds its own copy.
- suspended banner shown only for a suspended current org.
- logout: request sent, cache cleared, `/login`; failed request still clears and navigates.
- session-expiry scope:
  - a flagged request inside `_app` (e.g. an org-scoped query via `useOrgApi()`) answering `UNAUTHENTICATED` → cache cleared and navigation to `/login`;
  - a flagged request answering `PASSWORD_CHANGE_REQUIRED` → `/change-password`; while on `/change-password` → no navigation;
  - a credential mutation answering `UNAUTHENTICATED` (`auth.passwordChange` and `auth.twoFactor.enable` called from inside `_app`; `auth.login` on `/login`) → **no** navigation and the cache is **not** cleared (other cached queries still present);
  - `/invite` with no session renders (preview request only) and does not redirect;
  - an unflagged request answering `PASSWORD_CHANGE_REQUIRED` → no navigation.
- date helpers: Buddhist year and Bangkok time zone; `bangkokDayStartUtc("2026-10-24")` = `2026-10-23T17:00:00.000Z`.
