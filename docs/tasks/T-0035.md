# T-0035 · Verification HTTP and post-commit email delivery

## Goal

ทำเฉพาะขอบเขตใบนี้ตาม business decisions ที่อนุมัติแล้ว; technical design ใน spec amendment ต้อง merge โดยมนุษย์ก่อน execution

## Deliverables

- contracts identity `auth.email.verify.ts`, `auth.email.verification.resend.ts` + identity/index.ts; controller routes → use-cases matching endpoint keys
- verification 204 / approved field errors / INTERNAL; resend normalize, consume atomic quota before recipient branch, lock+rotate current eligible user then dispatch after commit
- verification email template fragment URL + sanitized failure handling through existing EmailSender public port
- export transaction-bound signup capture/after-commit dispatch for T-0011; native handler remains unmounted, no raw token return; no signup endpoint/global login switch

## Tests (เขียนก่อน)

- HTTP valid/invalid/malformed/expired/reused/replaced/wrong-purpose token; every specified error; no response body/session rows/Set-Cookie (including supplied cookie and malicious callback inputs)
- unknown/verified/managed recipients 204 and counted identically, no state/send; managed.invalid never mailed
- over quota/Valkey outage → 204 no rotation/send; sender failure → 204 new state retained; rollback sends nothing; no premature email before commit
- collector isolated across simultaneous requests; email link fragment not query; logs/audit/analytics redact token/PII; DB infra failure not mislabeled token error
- no tenant resource route: role denial/other-org endpoint cases N/A; repository ownership tests prevent unrelated user verification
