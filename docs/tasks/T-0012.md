## Deliverables

- `packages/contracts/src/org/`: Zod request/response contracts and inferred types for `org.get`, `org.update`, `branch.list`, `branch.create`, `branch.update`; export via the org index and root registry.
- `apps/api/src/modules/org/`: module/controller, use cases and tenant repository; register the module in `create-app.ts` (alphabetical, one registry entry per line). Keep existing bootstrap exports compatible.
- `GET /org`: `org.settings.read`; current organization's DTO only.
- `PATCH /org`: `org.settings.update` (owner only); editable business fields from the organization table, excluding slug/status and system-managed columns; `org.updated` audit in the same transaction.
- `GET /branches`: `org.settings.read`; owner/manager see the organization, branch-scoped roles see only assigned branches. Do not leak `orgId` in response DTOs.
- `POST /branches`: `branch.create` (owner only); enforce F05 atomically, map duplicate names within the same org to `CONFLICT`, create seven ISO weekday rows (09:00–18:00) and use `Asia/Bangkok`. Persist `branch.created` audit and outbox in the same transaction.
- `PATCH /branches/{branchId}`: `branch.update` (owner/manager); exclude PromptPay and tenant/system fields; foreign-org or absent target is `NOT_FOUND`; persist `branch.updated` audit/outbox atomically.
- If required, `subscription/branch-capacity.ts` exposes a transaction-bound public capacity operation through `subscription/index.ts`. Call only this public API from org; the public service owns subscription/plan reads and coordinates its locking with branch insertion in the same existing tenant transaction. No subscription/price/plan mutations.
- Reuse existing guards, `ctx.db.run`, injected time, `writeAudit` and `appendOutbox`; no platform DB shortcut. Extend test fixtures only as needed; do not weaken existing test assertions.

## Tests (write first)

- Real HTTP and Postgres integration for all five endpoints, persisted camelCase DTO fields, optional/null behavior once approved, and all applicable error codes.
- Permission matrix: all five roles can read org; only owner updates org/creates branches; owner/manager update branches; other roles denied writes.
- Missing/expired session → `UNAUTHENTICATED`; missing/malformed org header → `VALIDATION_FAILED`; non-member org header → `FORBIDDEN`; forced-password account → `PASSWORD_CHANGE_REQUIRED`.
- Branch lists never expose another org or an unassigned branch; foreign-org/nonexistent path IDs → `NOT_FOUND` for an otherwise authorized caller. Preserve guard ordering for callers without permission.
- Suspended organization: reads allowed, all three writes → `ORG_SUSPENDED`, no mutation/events/audit.
- Contract boundaries from the approved wire contract: name/display-name limits, tax ID, footer, coordinates/timezone, invalid UUID and forbidden input fields; validation envelope includes field details.
- Same-org duplicate branch name → `CONFLICT`; identical name across organizations allowed. Reject org slug/status and branch PromptPay writes without changing persisted values.
- At capacity → `PLAN_LIMIT_REACHED` (402), no branch/hours/audit/outbox; below capacity creates exactly seven hours rows. Concurrent requests with one slot left commit at most one new branch; the rejected request leaves no partial rows.
- Outbox rows match `#rule-branch-outbox`: create → `aggregateVersion` 1; each changing PATCH → `branch.version` + 1 and equal `aggregateVersion`; concurrent PATCHes on one branch yield distinct increasing versions; payload never contains `promptpayId`; `changedFields` sorted.
- Every required write produces the exact audit/outbox type and tenant/actor linkage; forced failure after mutation rolls back business rows, hours, audit and outbox together. No events on rejected requests.
