# T-0025 · Shop settings and branches (info tab)

## Goal

The owner edits the shop's details; owner and manager see the branches, open one, and edit its basic info; the owner adds a branch while the plan allows it. The branch page has the tab frame that T-0046 fills.

## Design

### `scr-settings-org` — `/settings/org` (owner)

- `GET /org`; form for `displayName` (required), `legalName`, `taxId` (13 digits), `phone`, `receiptFooter` (≤ 500). Empty optional field → sends `null` (clears it). Only changed fields are sent (`PATCH` needs ≥ 1); unchanged form → save disabled.
- Read-only: `slug`, `status`. `logoFileId` is not shown (no files feature yet).
- 200 → updates the cache; `VALIDATION_FAILED` → field messages; `ORG_SUSPENDED`, `FORBIDDEN` → `errors.ts`.
- A role other than owner opening the URL → the page shows `errors.FORBIDDEN` text (no request), since `org.update` is owner-only and §7 lists only owner.

### `scr-settings-branches` — `/settings/branches` (owner, manager)

- `GET /branches` → list: name, address, active/inactive badge; row → detail.
- "เพิ่มสาขา" button: only when `can(role, "branch.create")` (owner) **and** `GET /subscription` shows `usage.branches < plan.maxBranches` (or `maxBranches` null). At or over the limit the button is hidden and `limitReached` is shown with the plan name and numbers (§7: "ซ่อนเมื่อถึง limit พร้อมข้อความแพ็กเกจ").
- Add form (dialog): `name` (required), `address`, `phone`, `latitude` + `longitude` (both or neither; numbers, ≤ 6 decimals — client-checked with the contract). 201 → list refetch + navigate to the new branch. `PLAN_LIMIT_REACHED` (race) → `limitReached`; `CONFLICT` → `nameTaken`.

### `scr-settings-branch` — `/settings/branches/:branchId` (owner, manager)

- Layout route with tabs **ข้อมูล · เวลาเปิด-ปิด · วันหยุด · การชำระเงิน**; this card renders the frame and the ข้อมูล tab (index route). The other three tab links point to routes T-0046 adds; until then they show not-found. The การชำระเงิน tab link is visible to owner only (§7).
- The branch comes from the `branch.list` cache/query (there is no `GET /branches/{id}`); not in the list (other org, or not assigned per F02) → not-found state `notFound`.
- ข้อมูล tab: same fields as create + `isActive` toggle; `timezone` and `promptpayId` read-only (PromptPay is edited in the payment tab). Save sends only changed fields; 200 → cache update. `CONFLICT` → `nameTaken`; `NOT_FOUND` → `notFound`. Read-only form (no save button) when `!can(role, "branch.update")` — but only owner/manager reach this page anyway.
- api-client: `org.get`, `org.update`, `branch.list`, `branch.create`, `branch.update` in `endpoints/org.ts`; `subscription.get` in `endpoints/subscription.ts` (new file; one export line in `src/index.ts`).
