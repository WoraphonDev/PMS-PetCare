# T-0007 · Identity module

## Goal

พนักงาน login ด้วย email **หรือ** username + รหัสผ่าน ได้ session cookie, logout ได้, และ `GET /me` คืนผู้ใช้กับร้านที่เป็นสมาชิก

## Read first

- `docs/spec/features/foundation.md#ep-auth.login`, `#ep-auth.logout`, `#ep-me.get`, `#errors`, `#rule-F09`, `#rule-F11`
- `docs/spec/features/foundation.md#tbl-identity`, `#tbl-membership`
- `docs/adr/0001-stack.md` (Auth), `docs/adr/0003-multi-tenancy.md` (Tenant ของ request)
- `docs/spec/01-conventions.md`

## Deliverables

- `apps/api/src/common/db.ts`: Nest provider ของ `Db` (runtime) และ `PlatformDb` จาก `DATABASE_URL` / `DATABASE_PLATFORM_URL` (เพิ่มใน `config.ts`, `.env.example`)
- `apps/api/src/modules/identity/`:
  - `auth.ts`: Better Auth instance — drizzle adapter บน `@app/db` schema, `advanced.database.generateId` = uuid, plugins `username`,
    session cookie `HttpOnly`, `Secure` (ยกเว้น `NODE_ENV=development`), `SameSite=Lax`, ตั้ง `BETTER_AUTH_SECRET` จาก config
  - **ไม่ใช้** organization plugin ของ Better Auth — membership/invitation เป็นตารางของเราตาม spec
  - `use-cases/auth.login.ts`: `{ identifier, password }` — มี `@` → email, ไม่มี → username; เรียก Better Auth server API (ไม่ expose route ของ Better Auth ตรง ๆ)
    ตอบ `{ twoFactorRequired, mustChangePassword }` + `Set-Cookie`; ผิด → `UNAUTHENTICATED` (ข้อความเดียวกันไม่ว่า identifier มีหรือไม่)
  - rate limit ตาม `#rule-F11` (นับเฉพาะครั้งที่ล้มเหลว) — ตัวนับใน Valkey (key หมดอายุเอง) แยกเป็น `src/modules/identity/rate-limit.ts` ให้ T-0008 ใช้ซ้ำ
  - นโยบายรหัสผ่าน `#rule-F11` ใช้ใน contract (zod) ที่จะใช้ร่วมกับ signup/reset/change
  - `use-cases/auth.logout.ts`, `use-cases/me.get.ts` (`{ user, memberships: [{ org, role, branches }] }` — อ่านผ่าน `withPlatform` เพราะข้ามหลาย org ของผู้ใช้คนเดียว และกรองด้วย `user_id` เสมอ)
  - `identity.controller.ts` route ตาม spec; `AuthGuard` (session → `ctx.user`, ไม่มี → `UNAUTHENTICATED`)
  - บัญชี managed ที่ถูกปิด (F09) → login ไม่ได้
- contracts: `packages/contracts/src/identity/{auth.login,auth.logout,me.get}.ts`

## Tests (เขียนก่อน)

`apps/api/test/identity/*.test.ts` บน Postgres + Valkey จริง (Testcontainers; ใช้ `createTestDb` ของ `@app/db` และ Valkey container):
- login ด้วย email และด้วย username → 200 + cookie; รหัสผิด / ไม่มีผู้ใช้ → 401 `UNAUTHENTICATED` (body เหมือนกัน)
- ผิด 5 ครั้ง → ครั้งที่ 6 `RATE_LIMITED` แม้รหัสถูก; คนละ IP ไม่กระทบกัน; สำเร็จแล้วตัวนับรีเซ็ต
- `mustChangePassword` = true สำหรับบัญชี managed ใหม่
- logout แล้ว cookie เดิมเรียก `/me` → 401
- `/me` คืนเฉพาะ membership `active` ของผู้ใช้คนนั้น (มีผู้ใช้อื่นใน org เดียวกันและ org อื่นใน fixture)
- cookie flags ถูกต้อง; ไม่มี password/hash ใน response และ log
