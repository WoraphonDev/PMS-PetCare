# T-0049 · Branch hours read API

> Drafted by an agent at the human's request on 2026-10-24 for T-0046-01 (A); number assigned by the human on 2026-10-24. **Do not start implementation until a human has merged foundation §19 (PR #66) and this card.** A dev agent must not edit this card.

## Goal

Anyone who can read the shop settings can read a branch's current weekly opening hours, so the hours tab (T-0046) shows the real week before the user edits it.

## Read first (only the cited sections)

- `docs/spec/features/foundation.md`: §19 `#contract-branch-hours-get`, §12 `#contract-branch-hours` (G1 projection), `#ep-branch.closure.list` (the existing read with the same access rules), `#permissions`, F02, F04, F07, `#errors`.
- `docs/questions/T-0046-01.md`.
- Code: `apps/api/src/modules/org/org.controller.ts` (`GET branches/:branchId/closures`), the hours PUT use case and its projection, `packages/contracts/src/org/branch.hours.put.ts` (`BranchHoursPutResponse`), `apps/api/test/org/**` (schedule tests from T-0013).

## Contract (summary of §19 — the spec text wins)

- `GET /branches/{branchId}/hours` · `org.settings.read` · no body/query.
- `branchId` not a UUID → `VALIDATION_FAILED`; unknown, other org, or a branch role not assigned to that branch (F02) → `NOT_FOUND`.
- 200 `{ items: [{ weekday, opensAt, closesAt }] }` — exactly the PUT response projection: weekday asc, `HH:mm` or both `null`. Stored rows not matching the 7-weekday invariant → `INTERNAL` (no repair).
- Readable while suspended (F04). No lock, no version bump, no audit, no outbox.

## Deliverables

- Contract: `BranchHoursGetResponse` (reuse the PUT response schema — one shape for both) + status constant, exported from the org contracts barrel.
- Org module: read use case (tenant transaction, same branch lookup and F02 check as `branch.closure.list`, same projection mapping as the PUT) + route on the existing controller.

Size estimate: contract ~10, use case ~35, route ~15 → **about 60 non-test lines**.

## Tests (write first)

Integration tests on real Postgres.

- happy path: a new branch returns the default week (7 × 09:00–18:00); after a PUT with a closed day, the GET returns exactly the PUT response.
- response shape is exact (no id, branchId, timestamps or version) and weekday-sorted; times are `HH:mm` even though the DB stores `time`.
- every role with `org.settings.read` can read (owner, manager, front_desk, groomer, caretaker on their branch).
- branch role on a branch they are not assigned to → `NOT_FOUND`; other org's branch → `NOT_FOUND`; unknown id → `NOT_FOUND`; malformed id → `VALIDATION_FAILED`.
- suspended shop → 200.
- corrupted week (a test deletes one `branch_hours` row as the migrator) → `INTERNAL`.
- the GET writes nothing: `branch.version`, `updated_at`, `audit_log` and `outbox_event` unchanged.
- access: no session → `UNAUTHENTICATED`; missing/invalid `X-Org-Id` per the existing guard.
