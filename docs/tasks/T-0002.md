# T-0002 · apps/api skeleton

## Goal

API ที่บูตได้, ตอบ error ตาม envelope กลาง, มี health endpoint, และ dev environment (Postgres + Valkey + mail catcher) ด้วย `docker compose up`

## Read first

- `docs/adr/0001-stack.md`, `docs/adr/0002-modular-monolith.md`
- `docs/spec/01-conventions.md`
- `docs/spec/features/foundation.md#errors`
- `docs/spec/features/foundation.md#ep-system.health`

## Deliverables

- `apps/api/` (`@app/api`), NestJS + `@nestjs/platform-fastify`
  - `src/main.ts`: บูต HTTP, prefix `/api/v1`, `@fastify/helmet`, CORS อนุญาตเฉพาะ `APP_ORIGIN`, ปิด `x-powered-by`
  - `src/config.ts`: อ่าน env ด้วย zod — `NODE_ENV`, `PORT` (default 3000), `APP_ORIGIN`, `DATABASE_URL`, `VALKEY_URL`, `BUILD_SHA` (default `dev`); env ผิด → process exit พร้อมข้อความว่า key ไหนผิด (ห้ามพิมพ์ค่า)
  - `src/common/error.filter.ts`: แปลงทุก exception เป็น `ErrorResponse` ของ `@app/contracts` ตาม `errorHttpStatus`; zod error → `VALIDATION_FAILED` + `details.fields`; route ไม่พบ → `NOT_FOUND`; exception ที่ไม่รู้จัก → `INTERNAL` (500) โดย message ทั่วไป ไม่เปิดเผย stack/ข้อความภายใน (log เต็มฝั่ง server พร้อม request id)
  - `src/common/app-error.ts`: `class AppError(code: ErrorCode, message?, details?)`
  - `src/common/request-id.ts`: รับ/สร้าง `X-Request-Id` ใส่ใน response และ log
  - logger: redact `authorization`, `cookie`, `set-cookie`, `password`, `token`
  - `src/modules/system/system.controller.ts` + `use-cases/system.health.ts` ตาม `#ep-system.health`
  - `src/worker.ts`: entrypoint ของ worker (บูต Nest application context แล้วรอ — งานจริงมาในการ์ด outbox relay)
  - ~~`Dockerfile`~~ → ย้ายไป [T-0031](T-0031.md) (Q-0010)
- `docker-compose.yml` (root): `postgres:17-alpine`, `valkey/valkey:8-alpine`, `axllent/mailpit` — bind เฉพาะ `127.0.0.1`
- `.env.example`: ทุก key ใน `config.ts` พร้อมค่าตัวอย่างสำหรับ dev (ไม่มี secret จริง)

## Tests (เขียนก่อน)

`apps/api/test/system/system.health.test.ts` ใช้ Fastify `app.inject` (ไม่ต้องมี DB):
- `GET /api/v1/health` → 200 `{ status: "ok", version: <BUILD_SHA> }`
- route ที่ไม่มี → 404 envelope `NOT_FOUND`
- body JSON ผิดรูปบน route ทดสอบที่ validate ด้วย zod → 400 `VALIDATION_FAILED` + `details.fields`
- response มี `x-request-id`; ส่ง `X-Request-Id` มา → ตอบค่าเดิม
- route ทดสอบที่ throw `Error("secret detail")` → 500 `INTERNAL` และ body ไม่มีคำว่า `secret detail`
- response มี security headers ของ helmet; ไม่มี `x-powered-by`
- `apps/api/test/config.test.ts`: env ขาด `DATABASE_URL` → throw ที่ระบุชื่อ key และไม่มีค่า env อื่นใน message
