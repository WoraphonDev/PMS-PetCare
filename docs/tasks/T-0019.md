## Goal

A platform admin who has passed 2FA searches shops by name/slug and status, opens a shop's detail (plan, usage, owners), and suspends or reactivates a shop with a reason (US-F08). The status change is audited. Cross-shop reads use the platform connection through other modules' public APIs. The write runs in the shop's tenant transaction, so RLS still applies.

## Contract

### Fixed by the spec today

- `GET /platform/orgs?q&status&cursor`, `GET /platform/orgs/{orgId}`, `PUT /platform/orgs/{orgId}/status` `{ status, reason }`. All are platform admin only, with 2FA required (`TWO_FACTOR_REQUIRED`) and no `X-Org-Id`.
- Audit `platform.org_status_changed`.
- F04: a suspended shop reads but cannot write, and `platform.*` is exempt.
- ADR-0003: cross-shop work uses the separate connection, and platform writes are audited.

### Decided in §18 (summary — the spec text wins)

- **Reads** (`#contract-platform-org-read`):
  - list: `q` 1–100 is a case-insensitive substring of slug, displayName **or an active owner's email**; `status` filter; 50 per page, `createdAt` desc then `id`; `{ items, nextCursor }`; summary with plan and usage;
  - detail: organization + subscription (incl. `note`) + usage + active owners `{ userId, displayName, email | null, username }`;
  - malformed id → `VALIDATION_FAILED`; unknown → `NOT_FOUND`.
- **Read audit** (`#rule-platform-module`): every detail read writes `platform.org_viewed` (`entity_type 'organization'`, `entity_id` = org id, `before`/`after` null); list reads are not audited. The row's `org_id` waits for T-0019-04 (recommended: the target shop).
- **setStatus** (`#contract-platform-org-status`):
  - strict `{ status, reason (1–500) }`; unchanged status → 200 with nothing written;
  - audit `platform.org_status_changed` with the target shop's `org_id`, `before { status }`, `after { status, reason }`;
  - nothing else changes; 200 = detail.
- **Structure:** new `platform` module; cross-shop reads via public read functions of `org`/`subscription` on the platform connection; writes inside `withTenant`.

Out of scope: plan changes and the plan list (T-0020), platform UI, impersonation, deleting shops, notifying shops, auditing list reads.

## Tests (write first)

Integration tests run on real Postgres.

- **Contracts:** the query/body schemas and DTOs.
- **`apps/api/test/platform/platform.orgs.test.ts`:**
  - list:
    - search by slug, by name and by an active owner's email (case-insensitive); a removed owner's email does not match; status filter;
    - stable pagination across equal `createdAt`;
    - the usage counts match the limit rules;
    - another admin action does not change results;
    - bad query values / unknown keys → `VALIDATION_FAILED`.
  - detail: shape; managed owner email null; one `platform.org_viewed` row per read, with the `org_id` T-0019-04 decides (if the target shop: the shop owner sees it in `GET /audit-logs`; if null: the owner does not); a failed read (unknown id → `NOT_FOUND`, malformed → `VALIDATION_FAILED`) writes none.
  - setStatus:
    - suspend → the shop's next write answers `ORG_SUSPENDED` while reads work; reactivate → writes work again;
    - one audit row per effective change with the T-0019-02 content and `org_id`;
    - the shop owner sees it, with the reason, in `GET /audit-logs`;
    - unchanged status → nothing written;
    - reason missing / too long → `VALIDATION_FAILED`;
    - forced audit failure → `INTERNAL` and status unchanged.
  - access, for every endpoint:
    - no session → `UNAUTHENTICATED`;
    - a shop owner (not admin) → `FORBIDDEN`;
    - an admin without 2FA set up and an admin whose session has not passed 2FA → `TWO_FACTOR_REQUIRED`;
    - a suspended shop does not block `platform.*` writes.
  - module boundary: no file under `modules/platform/` imports another module's internals (a small static test, like other boundary checks if present; otherwise a grep-based test).
