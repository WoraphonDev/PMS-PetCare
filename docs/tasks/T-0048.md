# T-0048 · Account security

> Drafted by an agent at the human's request on 2026-10-24; split out of T-0027 (number assigned by Zo, 2026-10-24). **Do not start implementation until a human has merged this card and T-0024 and T-0045 are merged.** The Thai copy below is approved by merging this card. ## Goal

Any signed-in user changes their password and turns two-step verification on (scan a QR code, save backup codes, confirm with a code) or off; a platform admin can turn it on but not off.

## Read first (only the cited sections)

- `docs/spec/features/foundation.md`: `#scr-account-security`, `#ep-auth.password_change`, `#ep-auth.two_factor.enable`, `#ep-auth.two_factor.verify`, `#ep-auth.two_factor.disable`, F10, F11, `#errors`.
- `docs/tasks/T-0045.md` (`ChangePasswordForm`), `T-0024.md` (`me` query).
- Code: `packages/contracts/src/identity/auth.two-factor.ts`, `auth.password.ts`; `apps/api/src/modules/identity/use-cases/auth.two-factor.ts` (error mapping: wrong password/code → `UNAUTHENTICATED`, platform admin disable → `FORBIDDEN`).

## Design — `/account/security` (every user)

- **Change password:** reuse `ChangePasswordForm` (T-0045) in voluntary mode (no "forced" text). 204 → `passwordChanged` (other sessions are signed out by the API).
- **2FA status** from `me.user.twoFactorEnabled`.
- **Enable** (when off):
  1. password → `POST /auth/2fa/enable` → `{ totpUri, backupCodes }`;
  2. show a QR code of `totpUri` rendered **in the browser** with `qrcode` (`toDataURL` → `<img>`); never send `totpUri` to any external service; also show the secret (the `secret` parameter of `totpUri`) as text for manual entry;
  3. show the 10 backup codes with "คัดลอก" (clipboard) and "ดาวน์โหลด" (a `.txt` file made in the browser), plus `backupWarning`;
  4. code field → `POST /auth/2fa/verify` `{ code }` → 204 → refetch `me` → `enabled`. Until this succeeds 2FA is not on (the API activates it at the first verify).
  - The QR, secret and codes live only in component state; leaving the page discards them; nothing is written to storage or logs.
- **Disable** (when on, and **not** for `isPlatformAdmin`): password + code → `POST /auth/2fa/disable` → 204 → refetch `me` → `disabled`. Platform admins see `adminRequired` instead of the disable form.
- Errors: `UNAUTHENTICATED` on enable/disable → `wrongPassword` / `wrongPasswordOrCode`; on verify → `codeInvalid`; `RATE_LIMITED`; `FORBIDDEN` (admin disable) → `adminRequired`; `VALIDATION_FAILED` → fields.
- api-client: `auth.twoFactor.enable`, `auth.twoFactor.disable` (verify and change already exist from T-0045).

## Tests (write first)

- api-client descriptors.
- enable: password step → QR `<img>` with a `data:` URL (no network request other than the API), secret text parsed from `totpUri`, 10 codes; copy writes all codes to the clipboard (stubbed); download creates a text blob; verify 204 → `me` refetched → `enabled`; `UNAUTHENTICATED` messages per step; leaving the page and returning shows no codes.
- disable: hidden for platform admin (`adminRequired` shown); body `{ password, code }`; 204 → `disabled`; `UNAUTHENTICATED` → `wrongPasswordOrCode`.
- change password section uses `ChangePasswordForm` without the forced text.
- no `totpUri`, secret or backup code in `console` output or storage.
