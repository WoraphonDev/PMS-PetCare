# T-0045 · 2FA challenge, forced password change, forgot / reset

> Drafted by an agent at the human's request on 2026-10-24; split out of T-0023 (number assigned by Zo, 2026-10-24). **Do not start implementation until a human has merged this card and T-0023 is merged.** The Thai copy below is approved by merging this card. A dev agent must not edit this card.

## Goal

After login, a user with 2FA enters a 6-digit or backup code; a managed account with a password set by the shop changes it before anything else; an email user who forgot the password can reset it from the emailed link.

## Read first (only the cited sections)

## Design

- **`scr-auth-2fa` — `/login/2fa`:** one code field (6-digit TOTP or a backup code; contract `code` 1–128), checkbox "จำอุปกรณ์นี้ 30 วัน" → `POST /auth/2fa/verify` `{ code, trustDevice }` → 204 → navigate to `/` (the shell in T-0024 sends a `mustChangePassword` user on to `/change-password` from `me.get`). Errors, as `apps/api/src/modules/identity/use-cases/auth.two-factor.ts` maps them today: a wrong code **and** a missing/expired pending session both return `UNAUTHENTICATED`, so the UI shows one message `codeInvalid` that covers both, with a link to `/login`; `VALIDATION_FAILED` (`fields.code`) → field message; `RATE_LIMITED` → `rateLimited`; `INTERNAL` → `errors.ts`.
- **`scr-auth-change-password` — `/change-password`:** current password, new password (10–128), confirm (client-only equality check) → `POST /auth/password/change` → 204 → navigate to `/`. Used when `mustChangePassword` (F09); T-0048 reuses the form component for account security, so export it from `src/features/auth-recovery/`.
- **`scr-auth-forgot` — `/forgot-password`:** email → `POST /auth/password/forgot` → always the same acknowledgement `forgotAck` (the API always answers 204; F11). Text says reset works only for email accounts; managed accounts ask the shop.
- **`scr-auth-reset` — `/reset-password`:** read `token` from the query string on mount, then **immediately** `history.replaceState(null, "", "/reset-password")` so the token leaves the address bar and history; keep it in memory only. New password + confirm → `POST /auth/password/reset` `{ token, password }` → 204 → success + link to `/login`. `VALIDATION_FAILED` with `details.fields.token` → `tokenInvalid` + link to `/forgot-password`; other field errors → field messages. No token on mount → `tokenInvalid`.
- api-client: add `auth.twoFactor.verify`, `auth.passwordChange`, `auth.passwordForgot`, `auth.passwordReset` descriptors.

## Tests (write first)

- api-client descriptors (method, path, schemas, 204).
- 2FA: body `{ code, trustDevice }` (checkbox off → `false`); 204 → `/`; `UNAUTHENTICATED` → `codeInvalid` + link to `/login`; `VALIDATION_FAILED` → field message; `RATE_LIMITED` → `rateLimited`.
- change-password: mismatch blocks submit without a request; new password length checked client-side; 204 → `/`; `UNAUTHENTICATED` (wrong current password — `auth.password_change.ts` returns it) → field message on the current password; `VALIDATION_FAILED` → field messages.
- forgot: 204 → `forgotAck` for any email; malformed email blocked client-side.
- reset: token read from `?token=`, `replaceState` called before any request, URL afterwards has no query; body `{ token, password }`; 204 → `success`; `fields.token` error → `tokenInvalid` + link; no token → `tokenInvalid` with no request; token never in `console` output.
