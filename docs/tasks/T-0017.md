## Goal

Owners and managers change a member's role, branches or display name, and remove a member. F01 (last owner), F02, ¹ and F09 apply: removing a managed account disables it. Both writes follow the §14 check-and-lock protocol and write a §6 audit row in the same transaction.

## Contract

### Fixed by the spec today

- `PATCH /staff/{membershipId}` (`staff.update`): `{ role?, branchIds?, displayName? }`; F01, F02, ¹; audit `staff.role_changed`.
- `DELETE /staff/{membershipId}` (`staff.remove`): F01; audit `staff.removed`; F09 — a removed managed account cannot log in.
- F01 last active owner → `LAST_OWNER`. F02 branch roles need ≥ 1 branch → `BRANCH_REQUIRED`. ¹ / §8: a manager cannot act on owners/managers or make anyone owner/manager → `FORBIDDEN`.
- F04 `ORG_SUSPENDED`; F07 other-org ids → `NOT_FOUND`. §14: lock subscription → membership, and re-check after the locks.

### Decided in §16 (summary — the spec text wins)

- **Caller re-check** (`#rule-staff-caller-recheck`, pending confirmation): after the subscription lock and the org-status re-read, before the target lock and any write, re-read the caller's membership: not found / not `active` → `FORBIDDEN`; current role lacks the endpoint permission → `FORBIDDEN`. The ¹ manager rule uses this **current** role, not the role the guard read in phase 1.
- **Update** (`#contract-staff-update`):
  - strict PATCH, ≥ 1 field; `displayName` changes the membership only; the resulting role/branch state must be valid;
  - error order: guards → body → subscription lock + org status → caller re-check (`FORBIDDEN`) → target lock (`NOT_FOUND` incl. removed) → manager rule (current role) (incl. own membership) → `BRANCH_REQUIRED` / branch `NOT_FOUND` → `LAST_OWNER` → `#rule-managed-account-roles`;
  - no-op → 200 with nothing written; 200 `StaffMember`;
  - every effective change writes `staff.role_changed` with the changed fields only.
- **Remove** (`#contract-staff-remove`):
  - error order: guards → id → subscription lock + org status → caller re-check (`FORBIDDEN`) → target lock (`NOT_FOUND`) → manager rule (current role) → `LAST_OWNER`;
  - `status = 'removed'`, branch rows kept, audit `staff.removed`;
  - every session deleted **only for a managed account of this org**; real-email accounts keep their sessions;
  - 204.

Out of scope: password reset and account creation (T-0016), transferring ownership as one operation, removing pending invitations (T-0015 revoke), UI (T-0026), outbox events.

## Tests (write first)

Integration tests run on real Postgres through the existing harness. Every rejection compares a full snapshot (memberships, membership branches, audit, sessions of the target) before and after.

- **Contracts:** both requests, incl. the empty PATCH and strict keys.
- **`apps/api/test/org/staff.update.test.ts`:**
  - happy paths: role change branch → branch, branch → manager (branches cleared), manager → branch role (branches required), display name only, branch only;
  - each writes `staff.role_changed` with changed fields only;
  - 200 `StaffMember`; `GET /staff` reflects the change;
  - the changed member's next request sees the new scope (F02);
  - no-op → 200 with nothing written.
  - error precedence, one test per step plus a combined case:
    - guards (incl. `ORG_SUSPENDED`); body; absent / other-org / removed target → `NOT_FOUND`;
    - manager → owner/manager target, manager → promote to owner/manager, manager → own membership: all `FORBIDDEN`;
    - `BRANCH_REQUIRED`; unknown or other-org branch → `NOT_FOUND`;
    - demoting the last owner (incl. self) → `LAST_OWNER`; demoting one of two owners → 200;
    - caller re-check: while the request waits on the subscription lock, the lock-holding test transaction changes the **caller's** membership and commits — (a) caller removed, (b) caller demoted to `groomer`, (c) caller owner demoted to `manager` with an owner/manager target → `FORBIDDEN` in each case; no membership, branch, audit or session change;
    - `#rule-managed-account-roles`: a manager cannot promote anyone to owner/manager; an owner may promote a managed account.
  - concurrency (exactly two active owners A and B):
    - A and B demote **each other** to `manager` in parallel → one 200; the other `FORBIDDEN` (its caller is now a manager targeting an owner, by the caller re-check — not `LAST_OWNER`); one active owner remains; one audit row;
    - A and B each demote **themselves** in parallel → one 200, one `LAST_OWNER`; one active owner remains; one audit row.
  - suspension while waiting on the subscription lock → `ORG_SUSPENDED`.
  - atomicity: forced audit failure → `INTERNAL`, nothing changed.
- **`apps/api/test/org/staff.remove.test.ts`:**
  - happy path: 204; status `removed`; branch rows kept; audit `staff.removed`; seat freed (an invite that was `PLAN_LIMIT_REACHED` now succeeds);
  - the removed member's next request to this shop → `FORBIDDEN` (guard), while their other shop still works;
  - managed account: all its sessions deleted, login now fails;
  - real-email account: sessions kept (`#contract-staff-remove`).
  - error precedence per step, incl. manager rules, `LAST_OWNER` (also removing yourself as last owner), already removed → `NOT_FOUND`.
  - caller re-check: as in update — caller removed, or demoted to a role without `staff.remove`, or demoted to `manager` with an owner/manager target, while waiting on the subscription lock → `FORBIDDEN`; nothing removed, no audit, sessions unchanged;
  - concurrency (exactly two active owners A and B):
    - A and B remove **each other** in parallel → one 204; the other `FORBIDDEN` (its caller was removed, by the caller re-check — not `LAST_OWNER`); one active owner remains; one audit row;
    - A and B each remove **themselves** in parallel → one 204, one `LAST_OWNER`; one active owner remains; one audit row.
  - atomicity: forced audit failure → `INTERNAL`, membership and sessions unchanged.
- **`apps/api/test/identity/managed-account.test.ts`:** the session-deleting function removes every session of that account only.
