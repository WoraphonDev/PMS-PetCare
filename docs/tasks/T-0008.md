# T-0008 · EmailSender + password flows

## Goal

ลืมรหัสผ่าน / รีเซ็ต / เปลี่ยนรหัสผ่าน ตาม spec โดยส่งอีเมลผ่าน interface ของเรา (ADR-0005) — dev ใช้ Mailpit

## Read first

- `docs/spec/features/foundation.md#ep-auth.password_forgot`, `#ep-auth.password_reset`, `#ep-auth.password_change`, `#rule-F09`, `#rule-F11`
- `docs/adr/0005-external-services-and-cost.md` §1, §5 (Email)
- `docs/spec/features/foundation.md` §6 (audit `auth.password_reset`)

## Deliverables

- `apps/api/src/modules/notification/email/`: `EmailSender` interface (`send({ to, subject, text, html })`), `SmtpEmailSender` (nodemailer, config `SMTP_URL`, `MAIL_FROM`), `FakeEmailSender` สำหรับ test (เก็บข้อความในหน่วยความจำ)
- `auth.passwordForgot`: ตอบ **204 เสมอ**; มีผู้ใช้ email จริง (ไม่ใช่ managed) → ส่งลิงก์ `${APP_ORIGIN}/reset-password?token=…` (token ผ่าน Better Auth, อายุตาม `#rule-F11`)
  rate limit ตาม `#rule-F11` (ใช้ตัวนับ Valkey เดียวกับ T-0007)
- `auth.passwordReset`: `{ token, password }` → ตั้งรหัสใหม่, ล้าง **ทุก** session, audit `auth.password_reset`; token ผิด/หมดอายุ/ใช้แล้ว → `VALIDATION_FAILED` + `details.fields.token` (`#rule-F11`)
- `auth.passwordChange`: `{ currentPassword, newPassword }` → ล้าง `must_change_password`, ล้าง session อื่น (คง session ปัจจุบัน); รหัสเดิมผิด → `UNAUTHENTICATED`
- นโยบายรหัสผ่านตาม `#rule-F11` — ผิด → `VALIDATION_FAILED`
- ลิงก์/โทเค็นห้ามอยู่ใน log (URL ถูกตัด query แล้วจาก T-0002 — ตรวจซ้ำใน test)

## Tests (เขียนก่อน)

- forgot: มี / ไม่มี / บัญชี managed → 204 ทั้งหมด; ส่งอีเมลเฉพาะกรณีมีผู้ใช้ email จริง
- reset: token ถูก → login ด้วยรหัสใหม่ได้, session เดิมทุกตัวใช้ไม่ได้, มี audit 1 แถว; token ซ้ำ/หมดอายุ (ใช้ clock ทดสอบ) → 400
- change: รหัสเดิมผิด → 401; สำเร็จ → `mustChangePassword` false, session อื่นถูกล้าง, session ปัจจุบันยังใช้ได้
- ไม่มี token ใน log ที่จับได้
