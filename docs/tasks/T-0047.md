# T-0047 · Manage staff and accept invitations

## Goal

Owner and manager change a staff member's role, branches or display name, remove a staff member, and reset a managed account's password. An invited person opens the emailed link, sees the shop and role, and either logs in and accepts, or creates an account and joins.

## Design

### Row actions on `scr-staff` (owner, manager)

- Actions shown only when `canManageMember(myRole, member.role)` (¹ — manager cannot act on owner/manager rows, including their own row if they are a manager).
- **Edit** dialog: display name, role, branches (pickers from T-0026; manager sees only branch roles). Send only changed fields. Changing to owner/manager without touching branches sends no `branchIds` (the API clears them); changing from owner/manager to a branch role requires branches. 200 → refetch. Errors: `LAST_OWNER`, `BRANCH_REQUIRED`, `FORBIDDEN`, `NOT_FOUND` (already removed → refetch), `VALIDATION_FAILED`.
- **Remove** with confirm (names the person; managed accounts: "บัญชีนี้จะเข้าสู่ระบบไม่ได้อีก" — F09) → 204 → refetch. `LAST_OWNER`, `FORBIDDEN`, `NOT_FOUND` messages. Removing yourself: allowed by the API unless last owner; after success → clear org-scoped cache and refetch `me` (the shell picks another shop or `noOrg`).
- **Reset password** — only for `isManaged` rows: new temporary password (10–128) + show toggle → `PUT /staff/{id}/password` → 204 → panel: the person must change it at next login and all their sessions were signed out. `MANAGED_ACCOUNT_ONLY`, `FORBIDDEN`, `NOT_FOUND`.

### `scr-invite-accept` — `/invite#token=…` (public route)

- On mount: read the fragment; **first** `history.replaceState(null, "", "/invite")`, then keep the token in memory. No token → `invalid` state.
- `POST /invitations/preview` `{ token }` → show shop name, role label, branch names, invited email, expiry. `INVITATION_INVALID` → `invalid`; `ORG_SUSPENDED` → `suspended`.
- **Logged in** (cached/fetched `me` succeeds):
  - show "รับคำเชิญในชื่อ {me email or username}"; if `me.user.email` (lowercased) ≠ invited email, show `wrongAccount` warning (accept still allowed; the API decides);
  - accept → `POST /invitations/accept` `{ token }` → 200 → set the current org to `orgId` (T-0024 context), refetch `me`, navigate to `/`;
  - errors: `INVITATION_INVALID` (incl. managed account or email mismatch) → `acceptInvalid`; `ALREADY_MEMBER` → `alreadyMember` + switch to that shop; `ORG_SUSPENDED`.
- **Not logged in:** two choices.
  - "มีบัญชีแล้ว — เข้าสู่ระบบ": save the token to `sessionStorage` key `pms.pendingInvite` (via `src/lib/pending-invite.ts`, try/catch, cleared on read), go to `/login`. After login, `/` (`routes/index.tsx`) checks for a pending invite and, if present, navigates to `/invite` with the token restored into memory (never back into the URL).
  - "ยังไม่มีบัญชี — สมัคร": inline form — display name, password, confirm (email shown read-only from the preview) → `POST /auth/signup/invitation` → 201 → `signedUp` panel + button to `/login` (no auto-login). `CONFLICT` → `accountExists` with the login choice; `INVITATION_INVALID`, `ORG_SUSPENDED`, `RATE_LIMITED`, `VALIDATION_FAILED` → messages.
- The token is never logged, never put in a query string, and `sessionStorage` is the only place it is persisted (tab-scoped, cleared when used).
- api-client: `staff.update`, `staff.remove`, `staff.password.reset` (staff.ts); `invitation.accept`, `invitation.preview`, `auth.signupWithInvitation` (identity.ts — the invite endpoints are user/public, no `X-Org-Id`).

## Tests (write first)

- api-client descriptors (public/user ones send no `X-Org-Id`).
- row actions visibility per `canManageMember` (owner on any row; manager only on branch-role rows; reset only on managed rows).
- edit: only changed fields; role→owner sends no `branchIds`; owner→groomer requires branches; error mapping incl. `LAST_OWNER`.
- remove: confirm text (managed note); 204 → refetch; removing self → cache cleared + `me` refetched; `LAST_OWNER`.
- reset: length check; 204 → `resetDone`; `MANAGED_ACCOUNT_ONLY`.
- invite: `replaceState` before any request and URL has no hash afterwards; no token → `invalid` without a request; preview render; `INVITATION_INVALID` / `ORG_SUSPENDED` states; logged-in accept → org switched + `/`; `wrongAccount` shown on email mismatch; `ALREADY_MEMBER`; login detour stores the token in `sessionStorage`, `/` after login restores it to `/invite` with no token in the URL and clears storage; sign-up body `{ token, displayName, password }`, 201 → `signedUp`, `CONFLICT` → `accountExists`; token never in `console` output.
