## Design (technical defaults confirmed by the human on merge)

- Vite + React 19, `@vitejs/plugin-react`, Tailwind v4 via `@tailwindcss/vite`; imports `@app/ui/styles.css`.
- **Routing:** TanStack Router, file-based (`src/routes/`) via `@tanstack/router-plugin`. `routeTree.gen.ts` is **generated, not committed**: `apps/pms-web/.gitignore` lists it; the package's `typecheck`, `test`, `build` and `test:build` scripts run `tsr generate` first, and the nested `apps/pms-web/biome.json` ignores it. This keeps parallel screen cards from conflicting on one generated file.
- Routes in this card: `__root` (layout outlet, not-found and error components with Thai text from i18n, the update banner) and `/` (a placeholder that shows the app name — replaced by T-0023/T-0024; it is not a spec screen).
- **Server state:** one `QueryClient` (retry 1 for queries, 0 for mutations; never retry on `ApiError` 4xx), provided at the root; the router context carries `queryClient` and the `api` client.
- **API base URL:** `import.meta.env.VITE_API_BASE_URL`, default `/api/v1`. `vite.config.ts` proxies `/api` → `http://localhost:3000` in dev, so local dev is same-origin (run the API with `APP_ORIGIN=http://localhost:5173`). Production origin layout is decided with hosting (T-0030); cross-origin already works through the API's CORS allow-list.
- **i18n (T-0022-01 A):** a small typed in-house helper, no dependency.
  - one file per screen id under `src/i18n/th/` plus `common.ts`, each exporting a plain `as const` object; a barrel combines them (one line per file, alphabetical);
  - `t("common.appName")`, `t("scr-x.key", { name })` with `{name}` placeholders;
  - keys **and** placeholders are typed: unknown key, missing placeholder value, extra value, wrong placeholder name or wrong value type (values are `string | number`) fail `typecheck`;
  - this card adds only `common` keys it needs (app name, not-found, error, retry, `updateAvailable` = "มีเวอร์ชันใหม่", `update` = "อัปเดต"); `<html lang="th">`.
- **PWA** (`vite-plugin-pwa`, `generateSW` strategy, options in an exported object `pwaOptions` so tests read the same config the build uses):
  - Thai manifest (`lang: "th"`, `display: "standalone"`, `start_url: "/"`), placeholder icons (192/512 + maskable, a plain generated PNG — real brand icons are a human asset later);
  - **precache only built assets** (`globPatterns` limited to the emitted `js`, `css`, `html`, `webmanifest`, icon files);
  - **no runtime caching at all** (`runtimeCaching` empty) — tenant data and sessions never enter the Cache Storage;
  - **navigation fallback excludes the API:** `navigateFallback: "/index.html"` with `navigateFallbackDenylist: [/^\/api(\/|$)/]`, so `/api` and `/api/**` are never answered with the app shell;
  - result: with the network down, an API call fails and the client raises `ApiError` `INTERNAL` status 0 — never cached API data and never HTML from the app shell.
- **Update prompt (T-0022-02 A):** `registerType: "prompt"`; `src/pwa/` registers via `virtual:pwa-register` (`registerSW({ onNeedRefresh })`), with no periodic update timer in this card.
  - When an update is waiting, a non-blocking bar at the bottom shows `common.updateAvailable` and a button `common.update`; no dismiss button.
  - The app **never reloads by itself**. Pressing the button calls `updateSW(true)` once and disables the button. Pressing it does reload, so unsaved form data on the open page can still be lost — the card makes no promise that form data survives.
- Mobile-first: viewport meta; the shell has no horizontal scroll at 360 px.
- No auth, guards, org switcher, nav or real data in this card.

Out of scope: every `scr-*` screen, session handling and redirects (T-0023/T-0024), Playwright and any browser-automation dependency (T-0029), Docker/deploy of the web app (T-0032), LIFF, dark mode, languages other than Thai, offline features, draft saving for forms.

## Tests (write first)

### Source / config tests — `pnpm --filter @app/pms-web test` (part of `pnpm verify`)

Vitest + `jsdom` + Testing Library. **These tests never read `dist/`** and must pass on a clean checkout with no previous build; `vitest.config.ts` excludes `test/build/**`.

- **router:** `/` renders the Thai app name from the message file; an unknown path renders the not-found component (Thai text).
- **i18n (T-0022-01 A):** runtime — `t()` returns the Thai text and interpolates placeholders; type tests (`@ts-expect-error`, checked by `typecheck`) — unknown key, misspelled key, missing placeholder value, extra placeholder value, wrong placeholder name and a wrong value type each fail to compile; a correct call compiles.
- **update prompt (T-0022-02 A)** (`virtual:pwa-register` stubbed): no banner while no update is waiting; when `onNeedRefresh` fires, the banner shows "มีเวอร์ชันใหม่" and "อัปเดต" from i18n `common`; nothing reloads and `updateSW` is **not** called before the button is pressed; pressing calls `updateSW(true)` exactly once and disables the button (a double press still makes one call); there is no dismiss control.
- **PWA config** (reads `pwaOptions`): `registerType` is `"prompt"`; `globPatterns` match only built asset types; `runtimeCaching` is empty or absent; `navigateFallbackDenylist` matches `/api`, `/api/`, `/api/v1/me` and does not match `/`, `/settings/org`; manifest has `lang: "th"`.

### Build-artifact tests — `pnpm --filter @app/pms-web test:build` (separate command, in *Done when*)

- `test:build` = `tsr generate && vitest run --config vitest.build.config.ts`; the build tests live in `test/build/`.
- `beforeAll` runs a **fresh** Vite build programmatically (`build()` from `vite` with the app's config) into a new temporary directory created by the test, so the assertions always read output produced by this run — never an earlier `dist/`. The temporary directory is removed in `afterAll`.
- Assertions on that output:
  - `sw.js` and `manifest.webmanifest` exist; the manifest has `lang: "th"`;
  - every URL in the precache manifest inside `sw.js` names a file present in the output directory, and none is under `/api`;
  - `sw.js` contains the `NavigationRoute` with the `/api` denylist and registers no runtime route for `/api`;
  - `index.html` references the registration script.
- Not part of `pnpm verify` (CI is not changed by this card); the dev agent runs it and pastes the result in the PR.
