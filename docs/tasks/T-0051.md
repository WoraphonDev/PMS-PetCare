# T-0051 · Per-test timeouts for flaky signup API tests and the branch detail web test

> Drafted by an agent at the human's request on 2026-10-26 (T-0026-01, option A extended to the web test seen in T-0047). Same pattern as T-0039 and T-0050.

## Goal

Stop two tests from failing CI only under parallel load, so task PRs stop needing re-runs. Test-only change: no behaviour, assertion or production-code change.

## Read first

- `docs/questions/T-0026-01.md`: `signup.test.ts` › "rate-limits the sixth schema-valid attempt from one IP" timed out at 5000 ms (run 40163722430, attempts 1–2; 3716 ms on main), with the knock-on failure "leaves no row and sends no message when identity fails".
- CI run 40218455258 (PR #85, T-0047): `detail.test.tsx` › "shows the branch from the list: fields, timezone and PromptPay read-only" failed at `findByRole("link", { name: "ข้อมูล" })` — the default 1000 ms wait of Testing Library; the test took 1350 ms; local runs pass.
- `docs/tasks/T-0039.md`, `docs/tasks/T-0050.md` (the precedent)
- `docs/adr/0006-agentic-delivery.md` (tests define done; never weaken assertions)

## Deliverables

- `apps/api/test/identity/signup.test.ts`: one named constant at the top (e.g. `const MULTI_STEP_TIMEOUT_MS = 20_000;`) passed as the third argument of every `it(...)` that runs several signups / HTTP calls in sequence or concurrently (the rate-limit test, the concurrency and atomicity tests, and any test of the same shape), so the next slowest test does not become the new flake. If the knock-on failure comes from a late request of a timed-out test reaching the next test's collector, it disappears with the timeout; if not, fix the isolation inside this file without changing what is asserted.
- `apps/pms-web/test/settings-branches/detail.test.tsx`: give the screen-ready waits (the `findBy*` in the shared open helper and the first `findBy*` of each test that waits for route data) an explicit `{ timeout }` from one named constant (e.g. `const READY_TIMEOUT_MS = 5_000;`).
- Do **not** change global `testTimeout` / `asyncUtilTimeout`, any vitest config, other test files, assertions or production code.

## Tests

- The two test files are the deliverable. No `.skip`/`.only`/`.todo`, no altered `expect`.
- Evidence in the PR: local per-test durations before and after, and the CI `verify` result.
