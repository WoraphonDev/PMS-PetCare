## Goal

The owner reads the shop's audit log, newest first, filtered by date, action and actor, 50 per page (US-F07). Owner and manager see the shop's plan and how much of it is used, with the same counts the limits use (`#scr-subscription`).

## What already exists (do not re-create)

- `audit_log` rows written by every §6 action so far (RLS by `org_id`; platform rows have `org_id` null). Permissions `audit.read` (owner) and `subscription.read` (owner, manager).
- Seat count (`countSeats` in the org staff repository, single statement) and branch count (`countBranches`). These are org-internal today: expose read functions through `org/index.ts`, do not copy the SQL.
- `staffProfiles` (identity) for account names.
- No `audit` API module exists, and `subscription` has no controller.

## Contract

### Fixed by the spec today

- `GET /audit-logs?from&to&action&actorUserId&cursor` (`audit.read`): newest → oldest, cursor pagination 50 per page.
- `GET /subscription` (`subscription.read`): plan + current usage (branches, staff).
- Local dates `YYYY-MM-DD` and Asia/Bangkok (F06). RLS keeps every row in the caller's shop. Reads are allowed for suspended shops (F04).

### Pending human answers (recommendation in brackets)

- **T-0018-01 audit.list:**
  - [query keys only the five listed; `from`/`to` local dates, both inclusive, ≤ 366 days apart;]
  - [`action` ∈ §6; opaque cursor; `{ items, nextCursor }`;]
  - [items `{ id, occurredAt, action, entityType, entityId, actor: { userId, displayName } | null, before, after }`, without `ip`/`userAgent`.]
- **T-0018-02 index:** [one migration: `audit_log (org_id, occurred_at desc, id desc)`.]
- **T-0018-03 subscription.get:**
  - [`{ plan: { code, name, maxBranches, maxStaff, priceSatangPerMonth }, startedAt, currentPeriodEnd, usage: { branches, staff: { active, pendingInvitations, total } } }`;]
  - [no `note`, no plan `isActive`; missing subscription → `INTERNAL`.]

Out of scope: audit export, platform-level audit views (T-0019/T-0020), plan changes (T-0020), UI (T-0027).

## Tests (write first)

Integration tests run on real Postgres.

- **Contracts:** query schemas (dates, range limit, action enum, cursor, strict keys) and both response shapes.
- **`apps/api/test/audit/audit.list.test.ts`:**
  - order and page size: 120 seeded rows across equal timestamps → three pages in exact `occurredAt` desc, `id` desc order, no row repeated or skipped, last `nextCursor` null;
  - filters alone and combined; `from`/`to` boundaries in Asia/Bangkok (a row at 23:59:59.999 local is inside, 00:00 the next day is outside);
  - actor display name (current member, removed member, system actor null);
  - `ip`/`userAgent` absent;
  - another shop's rows and platform rows (`org_id` null) never appear;
  - `VALIDATION_FAILED` for each bad query value incl. an unknown key and a tampered cursor;
  - manager / branch roles → `FORBIDDEN`; guard errors; works for a suspended shop.
  - With T-0018-02 A/B: one test asserts the index exists (catalog query).
- **`apps/api/test/subscription/subscription.get.test.ts`:**
  - owner and manager get the shape;
  - counts equal the limit rules: inactive branch counted; a pending invitation counted, an expired one not; a removed member not counted; owner counted;
  - null limits; `note` never returned;
  - branch roles → `FORBIDDEN`; no subscription → `INTERNAL`; guard errors; works for a suspended shop.
