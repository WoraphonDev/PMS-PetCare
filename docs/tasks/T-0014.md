# T-0014 · Branch payment settings (PromptPay ID) API

> Drafted by an agent at the human's request, for human approval. **Do not start implementation until** (1) a human has merged this card together with foundation §13, and (2) T-0014-02 is answered and the check-digit formula is merged into `#rule-branch-promptpay-format`. A dev agent must not edit this card.

## Goal

The owner can set, replace or clear a branch's PromptPay ID with `PUT /branches/{branchId}/payment-settings`. The value is validated by F08 and written atomically with a version bump and a masked audit row, with no outbox event. The ID is the shop's receiving account for customer payments, so the card is `human_review: true`.

## Contract (summary of §13 — the spec text wins)

- Route `PUT /branches/{branchId}/payment-settings`, `@RequirePermission("branch.payment_settings.update")`.
- Body: strict `{ promptpayId }`, key required; a string that passes F08 after trim, or `null` to clear. Missing key, any other key or wrong type → `VALIDATION_FAILED` + `details.fields.<key>`.
- F08: trim leading/trailing whitespace only. No stripping of inner dashes or spaces, no `+66` conversion. Mobile `^0\d{9}$`. 13 digits with any first digit plus a valid check digit, using the formula from `#rule-branch-promptpay-format` once T-0014-02 is merged.
- Response: 200 `Branch` DTO with the real (unmasked) `promptpayId`. Query strings behave as in `branch.update`.
- Errors: `UNAUTHENTICATED`, `VALIDATION_FAILED`, `FORBIDDEN` (manager and branch roles), `PASSWORD_CHANGE_REQUIRED`, `NOT_FOUND` (absent / other org), `ORG_SUSPENDED`, `INTERNAL`. No error message or `details` contains the submitted value.
- Write: lock branch, compare after trim. Equal (incl. `null` → `null`) → 200 current DTO; no UPDATE, no version bump, no `updated_at` change, no audit. Changed → one `UPDATE` setting `promptpay_id`, `version = version + 1`, `updated_at = ctx.now` … `RETURNING version`, then audit in the same transaction. **No outbox event.**
- Audit: `branch.payment_settings_updated`, `entity_type 'branch'`, `entity_id` = branch id, actor = caller, `occurred_at = ctx.now`. `before`/`after` = `{ promptpayId }` **masked**: every digit before the last 4 becomes `*` (10 digits → `******5678`, 13 digits → `*********0123`), and `null` stays `null`. The full value must never be in the audit payload, application logs or error messages.

Out of scope: re-authentication or 2FA for this endpoint, extra rules for `is_active = false` branches, PromptPay QR generation (module `sales`), UI (T-0025), and any new error code, permission, audit action, outbox event, column or migration.

  - `lockBranch`, missing → `NOT_FOUND`;

## Tests (write first)

Run integration tests on real Postgres through the existing harness (`apps/api/test/org/support.ts`), with no mock repositories. Every error assertion checks the status, the envelope code and `details.fields` where relevant. It also checks that nothing was written: branch value, `version`, `updated_at` and audit rows.

- `packages/contracts/src/org/branch.payment_settings.contracts.test.ts`:
  - **Accepted:** valid mobile with surrounding whitespace (trimmed); `null`; valid 13-digit IDs, including a leading `0`.
  - **Rejected:** wrong check digit; 9/11-digit mobile; mobile not starting with `0`; 12/14 digits; letters; inner dash or space; `+66…`; empty after trim.
  - **Body shape:** missing key; extra keys (`version`, `name`, `orgId`, …); non-object, array and number bodies; `promptpayId` of type number or boolean.
- `apps/api/test/org/branch.payment_settings.update.test.ts`:
  - **Happy path:** owner sets a mobile, replaces it with a 13-digit ID, then clears with `null`. Each response is a 200 `Branch` DTO with the real value. The DB row and `branch.list` show the new value. `version` goes up by 1 and `updated_at = ctx.now` (fixed clock).
  - **No-op:** same value, same value with surrounding whitespace, and `null` → `null`. Each returns 200 with the current DTO, and `version`, `updated_at` and the audit count are all unchanged.
  - **Audit masking:**
    - mobile `0812345678` → `after.promptpayId = "******5678"`;
    - 13 digits → `*********` + last 4;
    - set from `null` → `before.promptpayId = null`;
    - clear → `after.promptpayId = null`;
    - replace 10 → 13 → both values masked.

    Also assert that the serialized `before`/`after` JSON of every audit row never contains the full submitted or previous value. Exactly one row per effective change, with `entity_type 'branch'`, `entity_id`, `actor_user_id` and `occurred_at = ctx.now`.
  - **No outbox:** no `outbox_event` row of any type after set, replace, clear or no-op.
  - **Atomicity:** force the audit insert to fail after the UPDATE → `INTERNAL`, and the branch value, `version` and `updated_at` are unchanged.
  - **Roles:** `manager`, `front_desk`, `groomer` and `caretaker` → `FORBIDDEN`. Manager is the key case, because it has `branch.update` but not this permission.
  - **Guard and route errors:** use `expectGuardErrors` for `UNAUTHENTICATED`, org-header `VALIDATION_FAILED`/`FORBIDDEN` and `PASSWORD_CHANGE_REQUIRED`. Also cover `ORG_SUSPENDED` on a suspended org, `VALIDATION_FAILED` for a malformed `branchId`, and every F08 failure.
  - **Tenant:** another organization's branch id → `NOT_FOUND`; unknown branch id → `NOT_FOUND`.
  - **No leak in errors:** for an invalid value, the error response body (message and `details`) does not contain the submitted string.
  - **Concurrency:** a parallel payment PUT and `branch.update` on the same branch both succeed with distinct consecutive versions. The `branch.updated` payload has no `promptpayId`, and its `changedFields` never lists it.
  - **Regression:** `branch.update` with `promptpayId` still returns `VALIDATION_FAILED`.
