# T-0005 · Identity tables

## Goal

ตาราง `user`, `session`, `account`, `verification`, `two_factor` ตาม schema ของ Better Auth + คอลัมน์ของเรา — id เป็น **uuid**
เพื่อให้ `membership.user_id`, `audit_log.actor_user_id` และตารางอื่นใช้ FK ชนิดเดียวกันได้

## Read first

- `docs/spec/features/foundation.md#tbl-identity`, `#rule-F09`, `#rule-F10`
- `docs/adr/0001-stack.md` (Auth)
- `docs/spec/01-conventions.md#database`

## Deliverables

- `packages/db/src/schema/identity/{user,session,account,verification,two_factor}.ts`
  - ชื่อตาราง/คอลัมน์ตามที่ Better Auth 1.7 ต้องการ (core + plugin `username` + plugin `twoFactor`) แต่ใช้ `casing: snake_case` ของเรา
    และ id ทุกตาราง = `uuid` (Better Auth: `advanced.database.generateId` จะตั้งใน T-0007)
  - คอลัมน์เพิ่มใน `user` ตาม `#tbl-identity`: `is_platform_admin`, `username` (citext unique, CHECK `^[a-z0-9._-]{3,40}$`), `is_managed`,
    `managed_by_org_id` (FK organization, CHECK: มีค่าเมื่อ `is_managed`), `must_change_password`, `two_factor_enabled`
  - ใช้ Better Auth CLI (`@better-auth/cli generate`) เป็นตัวอ้างอิงรายชื่อคอลัมน์ได้ แต่ไฟล์ที่ commit ต้องเป็น Drizzle schema ที่อ่านง่ายของเรา
- `audit_log.actor_user_id` → FK `user.id`
- migration ที่ generate (+ custom ถ้าต้องใช้ `citext`: `CREATE EXTENSION IF NOT EXISTS citext` — role `app_migrator` ต้องสร้างได้ใน test harness; ถ้าไม่ได้ → `docs/questions.md`)
- ตาราง identity **ไม่มี** `org_id` และไม่เปิด RLS (ADR-0003, `#tbl-identity`) — `rls-coverage.test.ts` ต้องยังผ่าน

## Tests (เขียนก่อน)

`packages/db/test/identity-schema.test.ts`:
- user id เป็น uuid; email unique; username unique แบบไม่สนตัวพิมพ์ (`Ann` ชน `ann`)
- username ผิดรูป → CHECK violation; `is_managed = true` โดยไม่มี `managed_by_org_id` → CHECK violation
- ลบ user ที่มี session/account → cascade ตามที่ Better Auth กำหนด
- `audit_log.actor_user_id` ที่ไม่มีอยู่ → FK violation
