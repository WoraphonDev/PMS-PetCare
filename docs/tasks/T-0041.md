# T-0041 · Test DB teardown waits for pool clients to close before stopping Postgres

## Goal

Stop CI `verify` from failing on **unhandled errors** while every test passes. The error is `57P01 terminating connection due to administrator command`, raised in a test file's teardown (seen in `apps/api/test/org/branch.update.test.ts`, PR #43 runs 39745076042 ×2; also T-0013 run 39737880596 and older runs). It was approved in chat on 2026-10-22 as a follow-up to T-0040. This is a test-harness fix only: no production code, assertion or test-file behaviour changes.

Root cause, from the pg-pool 3.14.0 source:
1. `createTestDb().stop()` calls `pool.end()` on each pool and then `container.stop()`.
2. `pool.end()` resolves once idle clients are **told** to end. `_remove` calls `client.end()` without waiting, and `_endCallback` fires when `_clients` is empty. Their sockets may still be open.
3. `container.stop()` makes Postgres send `57P01` to each backend that is still connected. The client's still-attached pool `idleListener` re-emits it as `pool.emit('error')`. The pool has no `'error'` listener, so the error is uncaught and vitest fails the run.

## Deliverables

- `test-db.ts` `stop()`: for each pool, wait until every client it held has really closed before `container.stop()` runs. For example, count `pool.totalCount` before `end()` and wait for that many `'remove'` events, which pg-pool emits in the `client.end()` callback. Keep it in one small helper with a one-line comment citing this card. Do not swallow errors with a blanket `pool.on('error', () => {})`, because that would hide real connection failures during tests.
- No change to `apps/api/test/support/infra.ts`, other test files, vitest config or production code.

## Tests (write first)

- `packages/db/test/test-db-teardown.test.ts` (new): create a test DB, check out and release clients on every pool so they sit idle, then call `stop()`. Assert that no pool emitted `'error'` and that `stop()` resolved only after every client's `'end'` event. Show RED on the current `stop()`, for example by asserting that the clients' `'end'` events have fired by the time `stop()` resolves.
